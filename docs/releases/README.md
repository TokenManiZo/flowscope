# 변경 기록

버전마다 바뀐 점과 업그레이드할 때 주의할 점을 여기에 정리합니다. 자세한 기록은 이 폴더에서 관리하고, GitHub Release 노트에는 세 줄 요약과 해당 버전 문서의 링크만 둡니다.

| 버전 | 날짜 | 요약 |
|---|---|---|
| [다음 릴리스 (미배포)](unreleased.md) | 미정 | ZAP 크롤링 범위 확대, LLM 브라우저 로그인과 탐색, 프로젝트 관리 창 |
| [v1.2.0-beta.50](v1.2.0-beta.50.md) | 2026-09-30 | 화면 전면 개편, 계정·세션 재설계, 권한 판정 매트릭스, 교차 신원 검증 |

## 쓰는 법

- 개발 중인 변경은 [unreleased.md](unreleased.md)에 모읍니다. 기능을 바꾸는 PR에 변경 기록도 함께 넣습니다.
- 릴리스할 때 `unreleased.md`를 `v<버전>.md`로 이름을 바꾸고 날짜를 적은 뒤, 빈 `unreleased.md`를 새로 만듭니다. 위 표에도 한 줄 추가합니다.
- 맨 위에 **주요 변경**을 두고, 그 아래는 **추가**, **변경**, **수정**, **제거**, **보안**으로 나눕니다([Keep a Changelog](https://keepachangelog.com/ko/1.1.0/) 분류). 해당하는 내용이 없는 항목은 지웁니다.
- 사용자가 알아야 할 것만 씁니다. 커밋 목록을 그대로 붙이지 않고, 테스트나 CI, 리팩터링처럼 동작이 바뀌지 않는 변경은 뺍니다.
- **업그레이드 주의**에는 프로젝트 저장 형식이 바뀌었는지, 다시 로그인해야 하는지 등을 적습니다.

## 스크린샷

- 화면이 바뀐 **주요 변경**에만 넣습니다. 버그 수정은 글로만 씁니다.
- `docs/releases/images/<버전>/` 아래에 둡니다. 미배포 기간에는 `images/unreleased/`에 두고, 릴리스 때 폴더 이름도 함께 바꿉니다.
- 한 번 릴리스된 이미지는 고치지 않습니다. 그 버전의 화면 기록이기 때문입니다. README의 이미지(`docs/images/`)만 최신 화면으로 바꿉니다.
- Burp 없이 화면만 띄우는 [Standalone 데모](../guide/build-from-source.md#standalone-데모)의 샘플 데이터로 찍습니다. 실제 대상 주소나 계정, 토큰이 보이면 안 됩니다.
- 1280×720 화면을 256색 PNG로 줄여 장당 100KB 이하로 맞춥니다.
