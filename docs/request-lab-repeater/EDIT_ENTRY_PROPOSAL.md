# Request Lab · +로 편집 진입하는 변경 목업

2026-10-04 사용자 피드백을 반영했고, 2026-10-05 승인 후 제품에 적용했다. 최종 구현과 한도는 [DESIGN.md](DESIGN.md)를 따른다.

## 확정된 화면

- 처음: `Original | +`. Original 요청·응답은 읽기 전용이며 수정할 수 없다.
- 첫 + 클릭: 기존과 같은 작은 드롭다운이 나타나고 편집 가능한 요청을 바로 표시한다. 편집을 시작하려고 드롭다운에서 현재 초안을 먼저 찾는 절차를 없앤다.
- 화면에 요청 탭들을 가로로 나열하는 안은 제외한다. 드롭다운과 Original은 같은 높이의 기존 디자인을 유지한다.
- 드롭다운 오른쪽은 `× | +` 순서다. ×는 현재 선택한 편집 요청과 마지막 응답을 제거한다. 원본 Evidence·Original·서버 감사 이력은 삭제하지 않는다. 다음 요청, 없으면 이전 요청을 선택한다. 마지막 요청을 지우면 드롭다운과 ×를 숨기고 `Original | +`로 돌아간다. Original에서는 ×를 비활성화한다.
- 오른쪽 요청 재전송의 아이콘·텍스트는 중앙 정렬, 설정과 보기 버튼 높이는 28px다.
- 요청은 편집 가능, 응답은 읽기 전용. 각 칸 내부 스크롤과 테마, 같은 칸의 색상 JSON 보기를 유지한다.

## 요청별 현재 상태

+를 누를 때마다 요청 1, 2, …를 추가한다. 요청별 재전송 이력은 만들지 않는다. #번호·HTTP 상태 이력 선택, 당시 편집 요청·읽기 전용 표시, 현재 편집/과거 이력 모드를 모두 제거한다.

`Original | +` → `Original | 요청 1 ▼ | × | +` → 드롭다운에 요청 2 추가. 현재 요청을 복사하고 새 요청의 응답은 비운다. 요청별 현재 편집 내용·인증·마지막 응답·스크롤을 독립적으로 유지한다. 원문으로 돌아갔다가 기존 요청을 다시 고르면 편집 내용을 복원한다. 첫 + 이후 추가 편집 진입 절차는 없다.

각 요청에는 **현재 REQ + 마지막 RES 하나**만 둔다. 재전송해도 해당 요청은 Raw 편집 상태를 유지한다. 이전 응답은 교체하며 별도 이력 배열에 남기지 않는다. 실제 전송 중에는 중복 클릭과 전송 값 변경을 잠그고 완료 후 바로 다시 편집한다. 응답은 읽기 전용이다. JSON은 기존 같은 칸의 표시용 보기를 유지하며 원문 전송 내용은 보기 전환으로 바꾸지 않는다.

응답을 받은 뒤 요청을 수정하면 마지막 응답은 유지하되 짧은 이전 응답 표시로 현재 수정본의 결과와 구분한다. 새 재전송 시작 시 이전 응답을 비우고 실패 시 응답 없음으로 표시한다. 이 동작은 과거 결과 보관 기능이 아니다.

## 적용한 원칙

- Original을 별도 불변 원문으로 유지하고 +는 복사본만 만든다. + 자체로 네트워크 요청을 보내지 않는다.
- 드롭다운 선택으로 미전송 편집을 잃지 않는다. 인증 방식도 다른 요청의 값으로 조용히 덮어쓰지 않는다.
- 응답은 전송한 요청 항목에만 적용한다. 다른 요청이나 이전 응답을 현재 전송 결과로 표시하지 않는다. 이전 전송의 Raw 복사본·응답 배열은 만들지 않는다.
- 비동기 결과의 소속과 데이터 generation을 함께 확인한다. 창 닫기·프로젝트 교체 이후 늦게 도착한 결과는 무시한다.
- 독립 요청이 여러 개면 메모리 예산을 요청 전체에 적용한다. 예산을 맞추려고 사용자의 미전송 편집을 자동 삭제하지 않는다. 현재 화면의 Raw는 기존 규칙대로 메모리에만 보관하며 프로젝트·브라우저 저장에 쓰지 않는다.
- 선택한 요청 하나만 편집기·색상 DOM에 렌더링하고, 전체 요청은 현재 프로세스 메모리에만 둔다. 기존 scope·HUMAN 승인·CRLF·전송 API를 유지한다.
