# Request Lab · 가독성·크기·인증 반영 수정안

2026-10-05 사용자 화면 피드백을 반영한 **승인된 목업**이다. 승인 후 제품에 반영했으며 제품 검증은 사용자 실행 대기다. 기존 Original·+·독립 요청·마지막 응답 동작은 유지한다.

## 목업에 반영한 네 가지

1. **상단 설정 가독성:** 인증·글자 크기·전체화면·요청 재전송을 36px 높이, 14px 글자로 표시한다. 제목은 22px, 보기 설정은 32px 높이로 구분한다. Original·요청 선택은 기존 104×28px를 유지한다. 제품의 90% density 영향을 받아 작아지지 않도록 설정 줄은 명시한 글자 크기를 사용한다. REQ/RES 글자 크기 선택은 독립적으로 유지한다.
2. **인증 변경 → 요청 반영:** 선택한 편집 요청의 관리 인증 헤더만 바꿔 바로 Raw에 표시한다. 비로그인은 제거, 현재 세션은 해당 URL에 유효한 최신 인증, 원문은 Original의 인증 헤더로 복원한다. Original·URL·method·일반 헤더·본문은 유지한다. 표시 전환은 Raw로 돌아오며 마지막 응답은 이전 응답으로 구분한다. 목업은 합성 인증 문자열만 사용한다.
3. **전체화면:** 기존 최대화를 `전체화면`으로 바꾸고 18px 아이콘과 더 뚜렷한 테두리를 사용한다. 브라우저 안의 남은 화면을 채운다. 버튼은 `원래 크기`로 바뀌고 Esc로 복원한다. OS/브라우저의 네이티브 Fullscreen API는 사용하지 않는다.
4. **넓은 기본 창·좌우 크기 조절:** 기본 너비는 화면의 90% 이내·최대 1680px로 시작한다. 목업의 화면 선택은 기본 너비만 정하며, 드래그 후에는 선택값의 제한을 받지 않고 실제 브라우저 너비에서 좌우 16px 여백까지 늘릴 수 있다. 좌우 경계와 아래 모서리를 드래그하고, 모서리는 방향키로 조절할 수 있다. 가로 중심은 유지하며 양쪽이 넓어진다. 최소 너비 960px·높이 460px를 기준으로 현재 화면 안에서 제한한다. 화면 높이가 더 작으면 화면 경계를 우선한다. 전체화면에서는 조절 핸들을 숨기며 복원 시 사용자가 정한 크기로 돌아간다. 기본 크기 버튼은 창 크기·패널 분할을 초기화한다. 크기는 현재 창에서만 유지한다.

## 현재 코드에서 확인한 차이

`RequestLabDialog`의 인증 선택은 현재 모드만 변경한다. `FlowScopeExtension.prepareHumanRequest`는 **실제 전송 직전** 관리 헤더를 제거하고 `SessionBroker.headersForAccount`의 인증을 적용한다. 따라서 비로그인을 선택했는데 요청 칸에 Cookie가 그대로 보이는 현재 화면은 실제 전송과 다를 수 있다.

현재 서버의 관리 대상은 Authorization·Cookie·Proxy-Authorization·X-CSRF-Token·X-XSRF-Token·X-CSRFToken이다. 그 외 헤더까지 임의로 삭제하거나 API key를 추측해 교체하지 않는다. 원문 모드로 전환할 때는 관리 대상만 Original에서 복원하며 편집한 본문을 통째로 되돌리지 않는다.

## 승인 후 구현할 경로

- 현재 전송 API와 scope·HUMAN 승인·operationId·CRLF·본문 인코딩 규칙을 유지한다.
- 전송과 동일한 서버 인증 적용 규칙을 사용하는 **전송 없는 미리보기**를 추가한다. 요청 URL의 exact scope, 선택 계정, cookie domain/path/secure·만료를 검증하고 필요한 관리 헤더만 돌려준다. 자동 HTTP 전송과 Evidence·감사 결과 생성은 하지 않는다.
- 미리보기는 기존 live HTTP 편집과 같은 로컬 인증 경계 안에서만 제공한다. 응답은 `no-store`로 처리하고 query cache·snapshot·프로젝트·로그·브라우저 저장에 넣지 않는다. 프런트에서 최신 인증값을 추측하거나 마스킹 값을 실제 전송 요청에 삽입하지 않는다.
- 프런트는 헤더 영역만 교체하고 본문 문자열/줄바꿈을 그대로 유지한다. 중복 관리 헤더·대소문자·CRLF/LF를 처리하고, 애매한 헤더 구분/잘못된 요청은 적용을 거부한다.
- 요청 ID·입력 revision·데이터 generation을 묶어 늦은 결과를 버린다. 처리 중에는 해당 요청 편집·선택·인증 변경·추가·삭제·전송을 잠근다. 실패하면 변경 전 모드와 요청을 함께 유지하며 이유를 짧게 표시한다. 다른 요청의 내용이나 인증을 바꾸지 않는다.
- 세션이 없거나 만료되면 자동으로 비로그인으로 바꾸지 않는다. 서버가 거부한 인증은 적용하지 않는다. 세션이 나중에 바뀔 수 있으므로 미리보기는 확인 시점의 값이며, 실제 전송은 기존 규칙대로 전송 시점의 최신값을 검증한다. 표시 요청을 최종 wire bytes와 동일하다고 주장하지 않는다.
- 전체화면·리사이즈는 편집기와 요청을 다시 마운트하지 않는다. drag 중 크기만 프레임 단위로 반영하며 pointerup에서 React 상태를 확정한다. 화면 변경 시 경계를 보정하고 내부 분할·스크롤·caret을 유지한다.

## 확인할 경우

- Original 보존, 세 가지 인증 왕복, 관리 헤더만 교체, 수동 본문/일반 헤더 편집 보존.
- 세션 없음·쿠키 경로 차이·scope 밖 URL·미리보기 실패·닫기/데이터 교체 후 늦은 응답.
- 본문 안의 인증처럼 보이는 문자열, 중복 헤더, CRLF/LF, 큰 Raw·메모리 한도와 파생 JSON 정리.
- 1280/1920px 라이트·다크, 큰/작은 창, 전체화면 복원, 좌우 핸들·키보드·화면 경계·REQ/RES 분할 충돌.

목업 확인과 제품 검증은 구분한다. 제품 빌드·테스트·Burp·Mac/Windows 실제 입력 검증은 사용자가 수행한다. 모바일은 제외한다. 이 수정안은 승인 후 제품에 반영했다.

목업 확인 결과: 이전 목업에서는 1280px에서 창 너비 1216px·설정 36px/14px와 헤더 영역 맞춤을 확인했다. 가로 크기 제한 수정 후 1280px의 기본 너비는 1152px이다. 1920px에서 좌우 모서리 방향키로 너비를 늘리고, 전체화면 1896×1056px에서 Esc로 사용자 크기 1712px로 복원했다. 인증 제거·현재 세션 교체·원문 인증 복원 시 편집 본문과 일반 헤더, Original 보존을 확인했다. 다크/라이트 캡처를 저장했다. 이는 합성 HTML 목업 결과이며 제품 테스트나 실제 포인터/Burp 검증 결과가 아니다.

가로 조절 수정 확인: 바깥 컨테이너의 1280px 최대 너비 제한을 제거하고 CSS와 포인터 계산의 최대 너비를 실제 화면 너비−32px로 통일했다. 2032px 브라우저에서 실제 마우스 드래그로 오른쪽 경계 1216→1496px, 왼쪽 경계 1496→1656px, 오른쪽 아래 모서리 1656→1756px 확대를 확인했다. 기존 문단의 포인터 미검증은 이전 목업에 해당한다. 이 포인터 확인은 합성 목업에서 수행했다. 승인 후 제품 리사이즈도 구현했으며 제품 검증은 사용자 실행 대기다.
