# Request Lab · 승인된 화면과 제품 설계

2026-10-05, `FEAT/request-lab-ui`에 승인된 목업을 적용했다. HTML 목업은 합성 데이터만 사용하며 제품 API를 호출하지 않는다.

## 화면과 동작

- 상단 첫 줄: 제목, 전송 인증, 글자 크기, 최대화, **요청 재전송**. 둘째 줄 맨 왼쪽: **Original | 요청 선택 | × | +**. 첫 요청을 만들기 전에는 **Original | +**만 표시한다. 오른쪽은 기본 크기·함께 보기·요청 확대·응답 확대다.
- Original·드롭다운은 104×28px, +·×는 28×28px다. 설정·보기 버튼도 높이 28px로 맞춘다. 오른쪽 요청 재전송 버튼은 아이콘과 글자를 중앙에 놓고 최소 너비 128px로 유지한다.
- 요청·응답은 헤더 바로 아래 남은 높이를 사용하며 각 칸 내부에서 스크롤한다. 기존 너비 분할·확대·색상·글자 크기를 유지하고 편집기를 다시 마운트하지 않는다.
- 별도 host·인증 상세·Raw 안내·메모리 안내·하단 전송 이력·정상 전송 메시지를 제거했다. 오류·일시 중지·원문 사용 불가 안내와 Burp handoff의 미전송 확인은 유지한다.

## 독립 요청과 마지막 응답

| 선택 | 요청 | 응답 | 동작 |
|---|---|---|---|
| Original | 보존한 관측 원문, 읽기 전용 | 관측 원문 | 직접 수정·전송 불가 |
| 요청 1, 2, … | 독립된 Raw 복사본, 편집 가능 | 해당 요청의 마지막 결과 하나 | 수정하고 직접 재전송 |

+는 현재 표시 중인 요청과 인증 방식을 복사하고 새 요청의 응답은 비운다. Original에서 추가하면 원문 인증을 사용한다. 실제 HTTP 전송은 +로 실행되지 않는다. 요청을 전환해도 편집 내용·인증 방식·마지막 응답·커서/스크롤을 유지한다. 번호는 삭제 후 재사용하지 않는다.

×는 선택한 편집 요청과 결과만 메모리에서 제거한다. 다음 요청, 없으면 이전 요청을 선택한다. 마지막 요청이 없어지면 Original로 돌아가며 드롭다운과 ×를 숨긴다. Original에서는 ×를 잠근다. Evidence·서버 감사 기록은 삭제하지 않는다.

요청마다 현재 REQ와 마지막 RES만 보관한다. #번호·HTTP 상태별 과거 결과 배열·당시 요청 읽기 전용·과거 요청 가져오기와 교체 확인은 제거했다. 재전송이 끝나도 Raw 요청은 바로 다시 수정한다. 응답은 읽기 전용이다. 요청/인증 변경 후에는 마지막 결과에 짧은 **이전 응답** 표시를 붙인다. 새 전송 시작 시 이전 응답과 파생 응답 JSON을 비운다. HTTP 4xx/5xx도 결과이며, 통신 실패는 응답 없음으로 표시한다.

## 수명·인증·전송

- 전송 중에는 편집·인증·Original·요청 선택·추가·삭제·중복 전송·handoff를 잠근다. 글자 크기·창/패널 확대는 사용할 수 있다.
- 결과는 전송을 시작한 요청 항목과 데이터 generation을 확인해 적용한다. 창 닫기·데이터 교체·unload에서 모든 요청/응답과 JSON 참조를 비우고 늦은 완료를 무시한다.
- 세션이 사라지면 기존 인증 선택을 보존하고 전송을 잠근다. 다른 인증으로 조용히 바꾸지 않는다. ACCOUNT는 전송 시점에 사용 가능한 현재 세션을 조회한다.
- Raw는 현재 창의 메모리에만 둔다. 프로젝트·브라우저 저장·query cache·로그에 복사하지 않는다. 서버의 기존 마스킹된 감사/검증 기록은 유지한다.
- exact-scope·HUMAN 승인·operationId·세션 검증·QA_TEMP의 CRLF 정규화와 본문 보존·전송 API는 변경하지 않는다. 자동/일괄 전송을 추가하지 않는다.
- 현재는 eventId 하나의 Original을 불러온다. 여러 관측 원문을 함께 고르는 기능은 추가하지 않는다.

## 성능과 한도

선택한 요청·응답만 렌더링하고 색상을 계산한다. 요청은 최대 32개이며 Original·각 편집 요청·마지막 응답의 UTF-16 텍스트 보관 예산은 JSON 출력/전송 복사본 예약 6MiB를 포함해 40MiB다. 한도 초과 시 추가·편집·응답 보관을 거부하며 미전송 요청을 자동 삭제하지 않는다. 큰 응답은 자르지 않고 보관하지 못했음을 안내한다. 브라우저 전체 heap/DOM 한도와는 다르며 서버의 Original 보관 한도를 크게 올리면 원문의 메모리가 늘 수 있다.

편집은 1,048,576 UTF-16 코드 단위까지, 실제 전송은 UTF-8 1MiB까지 허용한다. 거부된 편집 대신 이전 내용을 잘못 전송하지 않도록 내용을 줄일 때까지 전송을 잠근다. Raw가 256KiB 코드 단위를 넘으면 많은 토큰 DOM 대신 원문 텍스트로 표시한다.

JSON은 같은 칸의 색상 있는 읽기 전용 파생 보기다. 숫자·문자열 토큰과 Raw를 보존하고 전송은 항상 Raw를 사용한다. formatter 한도는 본문 256KiB·중첩 128단계·출력 1MiB, 색상 보기는 출력 64KiB다. 큰/잘못된 JSON은 Raw를 유지한다. 요청 전환 시 Raw 보기로 돌아간다.

## 검증 인계와 선택 이유

Original 보존·추가/복사/독립 선택·커서/스크롤/인증·삭제 후 이웃 선택·마지막 결과 교체·실패·전송 잠금·메모리 한도·참조 정리·늦은 응답에 대한 회귀 테스트를 수정했다. 제품 Maven/npm/tsc/Vitest/Playwright와 Burp 전송은 실행하지 않았다. 사용자가 빌드와 실제 검증을 수행한다. HTML 목업의 라이트·다크 확인은 제품 런타임 검증과 구분한다. 데스크톱 1280/1920px·Mac/Windows 입력은 사용자 확인 대상이며 모바일은 제외한다.

드롭다운은 요청 수가 늘어도 헤더가 길어지지 않는다. 과거 결과를 제거하면 편집 진입이 단순해지고 민감한 Raw 보관량이 줄어든다. 한도에 맞춰 다른 요청을 자동 삭제하는 방식은 미전송 편집 손실 때문에 제외했다. 기존 전송 API를 재사용해 scope·인증 검증을 유지한다.
