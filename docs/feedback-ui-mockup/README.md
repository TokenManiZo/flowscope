# FlowScope 화면 개선 목업

첨부된 관측 기록, API·입력 차이, 그래프 화면을 구체화한 **독립 인터랙티브 목업**이다. 기존 앱의 다크 테마와 정보 구조를 유지한다. 제품의 React·Java 코드를 변경하지 않는다.

## 관측 기록: 목록과 원문을 함께 읽기

왼쪽에는 요청 목록, 오른쪽에는 선택한 요청의 요약과 **Request / Response 가로 비교**를 배치한다. 기존 화면에서 긴 API 경로가 몇 글자씩 꺾이던 문제를 줄이기 위해 목록은 한 요청을 두 줄로 표시한다. 경로는 한 줄로 유지하고 나머지 공간에 출처·신원·시간을 둔다.

| 기능 | 동작과 목적 |
|---|---|
| 기록 선택 | 행 전체를 누르면 오른쪽 메서드·경로·신원·HTTP 상태·요청·응답이 함께 바뀐다. 선택 행은 배경과 테두리로 표시한다. |
| 메인 / 검토 필요 / 숨김 / 전체 | 기존 분류 구조를 유지한다. ‘검토 필요’는 사람의 확인이 필요한 기록이며 확정 취약점이라는 의미가 아니다. |
| 출처 필터 | HUMAN, SCANNER, LLM을 개별적으로 켜고 끈다. 검색 조건과 동시에 적용한다. |
| 검색 | 경로 또는 신원으로 목록을 줄인다. 결과가 없으면 조건을 바꿀 수 있도록 빈 상태를 보여 준다. |
| 요약 정보 | 긴 세로 메타데이터를 가로로 압축해 원문 영역을 확보한다. 출처와 실행 주체·도구를 별도 필드로 표시한다. |
| 가로 원문 | 요청은 왼쪽, 응답은 오른쪽. 두 영역은 독립적으로 가로·세로 스크롤한다. 상단 제목과 상태는 스크롤해도 유지된다. |
| 구문 색상 | 메서드, 헤더 이름, JSON 키·문자열·숫자, 마스킹값을 구별한다. 원문을 수정하거나 재직렬화하는 기능이 아니다. |
| 패널 너비 조절 | 가운데 경계를 드래그해 요청 영역을 30~70%로 조절한다. 경계에 키보드 포커스를 주고 좌우 방향키를 사용해도 된다. |
| 글자 크기 / 줄바꿈 | 12·13·14·16px 선택. 기본은 원문 줄 구조를 보존하고 가로 스크롤한다. 줄바꿈을 켜면 좁은 패널 안에서 읽을 수 있다. |
| 확대 | 요청·응답 영역을 창 대부분으로 확대한다. ‘확대 닫기’ 또는 Esc로 돌아온다. |
| 반복 묶음 | 목록에서는 대표 기록과 반복 수를 표시한다. 목업은 합성 대표본만 보여 준다. 제품에서 묶음을 삭제할 때는 연결된 모든 Evidence를 계산해야 한다. |

관측 기록은 **읽기 전용**이다. Request Lab과 같은 편집기 외형을 사용하지만, 여기서 요청을 수정·전송하지 않는다. 기존 Request Lab은 별도의 명시적 HUMAN 작업 흐름으로 유지한다.

Authorization·Cookie 등은 마스킹된 값만 표시한다. 실제 구현에서는 기존 마스킹 경로를 사용하고, 파싱할 수 없는 비밀 포함 본문은 기존처럼 숨긴다. 표시 편의를 위해 원본 비밀값을 DB·파일·로그·브라우저 저장소에 추가하지 않는다.

## API·입력 차이: 행 전체를 누르는 비교표

기존 `상세 보기` 버튼 열을 제거한다. 표의 행 전체를 클릭하면 우측 상세 패널이 열리고, API 이름 버튼에서 Enter·Space로도 접근한다. 오른쪽 작은 화살표는 클릭 가능하다는 보조 표시다. 상세 패널은 표의 선택 행과 함께 바뀌며, 닫으면 표에 공간을 돌려준다.

### H / S / L 표시

- **H**: HUMAN이 실제 요청을 생성했다.
- **S**: SCANNER가 실제 요청을 생성했다. 예를 들어 LLM이 ZAP을 시작해도 S다.
- **L**: LLM 탐색기가 실제 요청을 생성했다.
- **H− / S− / L−**: 해당 출처의 실제 관측 기록이 없다.

관측된 출처는 색상·배경·테두리로 표시하고, 미관측 출처에는 `−`를 붙인다. 색상만으로 상태를 구분하지 않는다. 상단 범례와 각 표시의 툴팁·접근성 이름이 의미를 설명한다. 중앙 디자인 토큰의 사람 파랑, 스캐너 보라, LLM 노랑을 사용한다.

‘선언’과 ‘관측’은 구별한다. 산출물이나 정의에서 경로를 발견했지만 아직 요청이 없으면 **산출물 API 후보 / HTTP 미관측**으로 표시한다. 이때 선언 1건이 있다는 이유만으로 H/S/L을 켜거나 API 존재·접근 가능을 확정하지 않는다. 과거의 LLM 평가 결과도 현재 관측 출처로 승격하지 않는다.

첨부 이미지에서 출처가 약하게 보이는 원인은 실제 데이터 없이 확정하지 않았다. 현재 `SourceMarks`는 소문자·대문자를 정규화해 표시한다. 실제 구현 때에는 연결된 관측 Evidence, source enum, CSS 대비를 함께 확인해야 한다.

| 기능 | 동작과 목적 |
|---|---|
| 표 정보 | Method, API, 관측 출처 H/S/L, 실제 HTTP 상태, 관측, 선언, 입력 수를 표시한다. HTTP 상태가 여럿이면 함께 보여 준다. |
| 행 선택 | 메서드·경로·입력 정보·연결 관측 기록을 우측 패널에 보여 준다. 별도 확인창이나 페이지 이동 없이 비교를 이어 간다. |
| 검색 | 메서드 또는 경로로 비교표를 줄인다. |
| 필터 | 전체, 선언만 있고 미관측, 출처 간 관측 차이, HUMAN/SCANNER/LLM 관측을 선택한다. ‘출처 간 차이’는 알려진 API의 관측 차이이며 전체 서비스 점검률이 아니다. |
| 입력 상세 | path/query/body 위치, 이름, 형식과 근거를 보여 주는 영역이다. 목업은 위치·이름·형식과 예시 근거만 표시한다. 실제 값 차이와 출처별 shape 비교는 기존 데이터 연결이 필요한 후속 구현이다. |
| 관측 기록 이동 | 상세 패널에서 #기록을 누르면 관측 화면으로 이동해 그 요청·응답을 연다. 기존 검색 필터 때문에 대상 기록이 숨지 않도록 조건을 해제한다. |
| 미관측 상세 | ‘아직 요청이 관측되지 않았습니다’와 ‘실제 존재 여부 미확인’을 보여 준다. 요청 원문을 만들어 채우지 않는다. |

목업 표의 관측 수는 대표 관측 항목 수다. 반복 요청 수와 구별한다. 제품에서 사용할 집계 단위는 기존 snapshot 계약과 맞추고, 삭제 확인에는 반복으로 묶인 실제 대상 기록 수까지 명확히 표시한다.

## 그래프: 탐색과 기록 삭제

왼쪽 필터, 중앙 관계 그래프, 오른쪽 현재 보기 패널 구조를 유지한다. API 노드를 선택하면 오른쪽에 경로·출처·신원·객체·관측 기록이 나타난다. 그래프의 HTTP 상태는 관측값으로 보여 주고, 상태만으로 ALLOW/DENY 또는 취약점 판정을 만들지 않는다.

| 기능 | 목업 동작 / 제품 설계 |
|---|---|
| 출처·신원·상태 필터 | 표시할 연결과 API 노드를 줄인다. 관련 기록이 없는 노드는 감춘다. 원본 기록 삭제와는 별개의 탐색 기능이다. |
| 검색 | API 경로, 객체 ID, 접근한 신원으로 그래프를 줄인다. |
| 드래그 이동 | 빈 캔버스를 드래그해 그래프를 이동한다. |
| 확대·축소 | 버튼은 현재 배율의 1.2배 / 1.2분의 1배. 슬라이더는 40~180%. 휠은 커서 위치를 기준으로 연속 확대한다. 한계에서는 버튼을 비활성화한다. |
| 전체 맞춤 | 현재 표시된 노드를 화면에 되돌리는 빠른 복구 수단이다. 목업의 고정 좌표 예시는 100%·중앙 위치로 복귀한다. 제품은 실제 노드 경계에 맞춰 fit해야 한다. |
| 미니맵 | 기본 펼침. 오른쪽 위 닫기 버튼으로 접고 툴바 버튼으로 다시 펼친다. 미니맵을 클릭하면 해당 위치가 화면 중앙으로 이동한다. |
| 초기화 | 그래프 필터·검색·배율·위치를 초기화한다. 삭제한 기록을 복구하는 동작이 아니다. |
| 키보드 | API 노드에서 Enter·Space로 상세를 연다. 확대·축소·미니맵은 키보드로 접근 가능한 버튼을 제공한다. |
| 관측 연결 | 우측 #기록 버튼으로 해당 요청·응답을 연다. |

실제 앱에는 이미 휠 입력 구분과 미니맵이 있다. 제품에서는 이 경로를 개선하며, 목업의 단순 SVG를 Cytoscape 대체 엔진으로 도입하지 않는다. 마우스는 휠 확대, 트랙패드는 두 손가락 이동과 핀치 확대를 구별하는 기존 입력 방식이 유지되어야 한다. 배율 변경은 viewport만 바꾸고 노드 모델 좌표를 재배치하지 않는다. 미니맵·엣지·라벨 갱신은 화면 프레임에 맞춰 제한한다. ‘더 빠르게’에 대한 실제 성능 수치는 제품 데이터와 장치에서 측정한 뒤 판단한다.

### 휴지통과 작은 삭제 확인창

사용자가 선택한 동작은 **API와 연결된 원본 관측 기록까지 삭제**다. 그래프에서만 숨기는 안은 채택하지 않았다. 휴지통은 오른쪽 ‘현재 보기’ 제목 옆에 둔다. API 선택이 없으면 삭제 버튼을 표시하지 않는다.

1. 휴지통을 누른다.
2. 약 440px 너비의 확인창에 메서드·전체 경로·연결 관측 수·반복을 포함한 요청 수를 표시한다.
3. 현재 필터로 가려진 기록도 삭제된다는 점과 되돌릴 수 없다는 점을 설명한다.
4. 취소·닫기·Esc는 삭제 없이 돌아온다. 최초 포커스는 안전한 취소 동작에 둔다.
5. `API와 기록 삭제`를 누르면 해당 API 노드와 연결 기록을 제거하고 세 화면의 목록·집계를 갱신한다. 성공 알림은 완료 후 보여 준다.

목업에서 `/api/users/me/profile`을 삭제하면 대표 관측 기록 3건, 반복 묶음 포함 요청 5개가 대상이다. API 표는 7→6개, 관측 목록은 전체 8→5개, 관측된 API 노드는 3→2개로 바뀐다. 제품 동작에는 되돌리기를 제안하지 않는다. 목업 새로고침은 합성 데이터를 다시 만드는 개발용 초기화다.

### 실제 삭제 구현 전에 확정해야 하는 계약

화면을 승인하더라도 이 데이터 삭제 기능은 아직 제품에 없다. 다음 조건을 지켜 구현한다.

- **정확한 대상:** 현재 프로젝트·datasetRevision과 서비스 origin + 메서드 + 정규화 경로를 함께 사용한다. 같은 경로의 다른 서비스나 메서드를 삭제하지 않는다. 반복 cluster의 모든 Evidence ID와 숨김 기록을 포함한다.
- **Evidence 참조 보호:** 과거 LLM 평가·verdict 아카이브 또는 기존 사람 감사 기록이 참조하는 Evidence를 삭제해 참조를 깨뜨리지 않는다. 이러한 참조가 있으면 삭제를 차단하고 이유를 설명한다. 별도 보존 정책이 승인되기 전까지 강제로 링크를 끊는 옵션은 제공하지 않는다. 목업 데이터에는 이 보호 참조가 없다.
- **관련 데이터:** 삭제한 관측에 종속된 입력 관측·그래프 연결·파생 집계만 갱신한다. 공유 신원·객체, 계정·세션, 다른 API Evidence, 소유자·역할 정책을 함께 지우지 않는다. 삭제 대상 밖의 archive와 audit는 그대로 보존한다.
- **선언 근거:** 가져온 정의 파일·산출물 원본의 선언까지 지우는 요청은 아니다. 목업은 삭제한 API 행을 현재 데이터 화면에서 제거한다. 실제 제품에서 선언으로 남은 경로를 후보로 다시 표시할지에 대한 처리는 구현 전 확정해야 한다.
- **새 관측:** 이후 같은 API 트래픽이 다시 들어오면 새 관측으로 다시 나타날 수 있다. 영구 수집 차단이나 점검 scope 변경을 뜻하지 않는다.
- **확인 후 변경:** 확인창을 연 뒤 데이터셋이 바뀌거나 새 기록이 들어와 대상 수가 달라지면 삭제를 중단하고 최신 대상 수로 다시 확인한다.
- **서버 성공 이후 표시:** 실제 삭제·연결 갱신·프로젝트 저장 성공을 하나의 일관된 작업으로 처리하고, 실패하면 기존 목록과 선택을 보존한다. 진행 중 버튼 중복 실행을 막으며, 실패 메시지는 비밀값 없이 이유와 재시도를 제공한다.
- **메모리 정리:** 삭제한 Evidence가 선택되어 있거나 해당 Request Lab 초안이 열려 있으면 무효화하고 그 기록의 현재 프로세스 raw 메모리를 정리한다. 프로젝트 교체·unload의 기존 정리 규칙도 유지한다.

## API 수동 강조 목업

API를 다시 찾기 위한 사용자의 표시다. 기본 예시는 profile API의 노랑, issues API의 분홍이며 사용자가 직접 변경할 수 있다.

1. 그래프에서 API 노드를 선택한 뒤 오른쪽 제목 옆 형광펜을 누른다. 노드를 우클릭해도 같은 팝오버가 열린다. API 비교표에서는 상세 패널의 형광펜을 사용한다.
2. 3×3 팔레트의 9가지 고정 색상을 고른다. 선택한 색에는 체크 표시·색 이름이 있으며, 클릭하면 바로 적용되고 팝오버가 닫힌다. 별도 저장 버튼은 없다.
3. API 카드와 비교표 행은 은은한 배경색, 미니맵 API는 같은 색으로 표시한다. 카드와 표에는 작은 색 점, 상세에는 `수동 강조 · 색 이름`을 표시한다. 기존 선택 테두리, 출처·HTTP 상태 표시를 유지한다. 신원·객체 노드와 연결선은 함께 칠하지 않는다.
4. 다시 팝오버를 열어 색을 바꾸거나 `강조 해제`를 누른다. 아직 강조하지 않은 API에서는 해제 버튼이 비활성화된다. 닫기, Esc, 바깥 클릭은 적용 없이 닫는다.
5. 그래프 왼쪽과 API 표 상단의 `강조된 API만`으로 목록을 좁힌다. 검색·기존 필터와 함께 적용한다. 강조를 모두 해제해 결과가 없어져도 그래프 초기화로 복귀할 수 있다.

화면을 이동하거나 그래프 필터·위치를 초기화해도 색상은 유지된다. API를 삭제하면 그 API의 강조도 제거한다. 목업에서는 현재 페이지의 메모리만 사용하며, 새로고침하면 기본 합성 예시로 돌아온다. 프로젝트 파일·브라우저 저장소·Burp 주석과 동기화하지 않는다.

실제 구현에서는 프로젝트별로 서비스 origin + 메서드 + 정규화 경로에 연결해 저장한다. 같은 API의 다른 신원·출처 관측은 같은 색을 공유하되, 다른 서비스나 다른 메서드의 API에는 전파하지 않는다. 배치 좌표와 독립된 메타데이터로 저장해 프로젝트 재열기·노드 접기·배치 초기화에도 유지한다. 구버전 프로젝트의 기본값은 강조 없음이며 기존 archive·audit·Evidence를 보존한다. 저장 실패 상태를 안내하는 서버 연결은 후속 구현이다.

색상에는 취약·안전·완료 등의 판정 의미를 부여하지 않는다. 자유 색상 선택, 색상별 사용자 이름, 자동 규칙, 다중 노드 일괄 적용, Burp 색상 가져오기는 이번 목업에 포함하지 않았다.

## API 보안 검토 목업

API 상세의 형광펜 옆에 `보안 검토` 버튼을 둔다. 그래프 노드와 API 비교표의 `취약점 N`·`검토 필요 N` 배지도 같은 검토 패널을 연다. 노드 배경은 사용자의 강조색을 유지하고, 작은 빨강·주황 배지에서 이름과 개수를 표시한다. 배지 색은 상태를, 별도의 심각도 필드는 영향을 나타낸다. HTTP·H/S/L 색이나 선택 테두리를 덮지 않는다.

| 동작 / 필드 | 목업의 동작 |
|---|---|
| 항목 등록 | API 하나에 여러 항목을 등록한다. 이름과 메모를 남겨 `검토 필요`로 저장할 수 있다. |
| 검토 상태 | `검토 필요 / 확인됨 / 오탐`. 확인된 항목만 취약점 개수에 포함한다. 오탐은 활성 배지에서 빠지지만 목록과 변경 이력에 남는다. |
| 심각도 | `미정 / Critical / High / Medium / Low / Info`. 상태와 독립적으로 지정하며 HTTP 상태에서 자동 산출하지 않는다. |
| 근거 관측 기록 | 해당 API의 마스킹된 관측본을 여러 개 선택한다. `보기`는 해당 관측 기록 화면으로 이동한다. 저장 전 초안은 버려진다. |
| 확인 저장 | 이름·근거 기록·판단 이유를 요구한다. BOLA/BFLA는 기대하는 소유자·역할 정책도 요구한다. 미관측 API는 확인 저장할 수 없다. 필드 존재를 검증하는 UI 예시이며 내용의 정확성을 자동 판정하지 않는다. |
| 오탐 저장 | 오탐으로 변경한 이유를 요구한다. `활성 항목 없음`은 안전 판정을 의미하지 않는다. |
| 변경 이력 | 저장 전 이름·상태·심각도·유형·근거·정책·메모의 메모리 사본을 유지한다. 이전 상태·이유·근거는 접힌 이력에서 읽을 수 있다. |
| 상태 필터 | 그래프와 API 표에 각각 전체·검토 필요·취약점 확인·오탐 기록 필터가 있다. 기존 검색·출처·강조 필터와 함께 적용한다. 그래프 초기화는 검토 필터를 풀고 검토 항목은 보존한다. |
| 삭제 보호 | 현재 검토 항목 또는 이전 변경이 관측 기록을 참조하면 API·관측 삭제를 차단한다. 오탐 처리나 현재 근거 해제로 이전 참조를 삭제하지 않는다. 참조가 없는 API에는 기존 삭제 흐름을 유지한다. |
| 닫기 | 닫기 버튼·Esc로 닫고 정확한 진입 버튼 또는 배지에 초점을 돌려준다. 상태 변경으로 원래 배지가 사라지면 검토 버튼 또는 필터로 돌아간다. 저장 전 입력은 버려지며 실제 요청 전송은 없다. |

초기 합성 예시는 프로필 API의 확인됨 1개·검토 필요 1개, 프로젝트 API의 검토 필요 1개다. **확인됨 예시는 배지와 폼의 모양을 보여 주는 가상 검토 결과이며, 기존 합성 HTTP 응답이 취약점을 입증한다는 뜻이 아니다.** 패널에도 이 구분을 명시한다. 검토 항목·이력은 현재 페이지 메모리에서만 유지하고 새로고침하면 예시로 복귀한다. 실제 프로젝트 저장·사용자 식별·서버 감사 로그·자동 탐지는 구현하지 않는다.

실제 구현에서는 API 표시와 Evidence에 연결된 사람의 검토 기록을 구분해 저장하고, 서버에서도 확인 조건과 참조 보호를 검증해야 한다. BOLA/BFLA 판단은 저장된 근거와 소유자·역할 정책에 기반한 사람의 판단이며, 과거 LLM 평가를 현재 확인 항목으로 변환하지 않는다. 자동 확정, 전체 노드 위험색 도색, `안전` 배지, CVSS 계산·보고서 생성은 이번 범위에서 제외했다.

## 화면 크기와 표현 규칙

- 1600px에서는 넓은 원문 가로 비교와 그래프 3영역을 기본으로 한다.
- 1280px에서는 좌측 목록·필터와 우측 패널을 줄여 중앙 영역을 확보한다.
- 850px 이하에서는 관측 목록과 원문을 위아래로 배치하고, 요청·응답도 세로로 바꾼다. API 표는 자체 가로 스크롤, 상세는 표 아래, 그래프 상세는 캔버스 아래에 둔다.
- 색상 외에 텍스트·테두리·선택 상태를 함께 사용한다. 컨트롤은 키보드 포커스 표시를 제공한다.
- 점검률·완료율은 표시하지 않는다. 블랙박스 서비스 전체 API 수를 알 수 없으므로 현재 알려진 목록의 개수만 보여 준다.

## 변경 범위와 채택하지 않은 대안

변경은 이 목업 폴더 안에서만 진행했다. 기존 앱을 바로 수정하는 대신 독립 HTML/CSS/JS로 의도와 조작을 검토할 수 있게 했다. 원문 열람을 요청 편집·재전송으로 확대하지 않았다. API 행마다 상세 버튼을 남기는 안은 요청에 따라 제거했다. 그래프 삭제를 단순 숨김으로 처리하는 안은 사용자의 답변에 따라 제외했다. 데이터 삭제에는 되돌리기 성공을 약속하지 않는다.

실제 구현 관련 영역은 `OperationDetail`, `RawTextPanel`, `SurfacePage`, `SourceMarks`, `CytoscapeGraph`, `GraphInspectorPanel`이다. 표시 변경과 프로젝트 데이터 삭제 계약을 분리해 검토해야 한다. 기존 Explorer를 재작성하거나 제거된 Judge/MCP를 복원하는 범위는 포함하지 않는다.
