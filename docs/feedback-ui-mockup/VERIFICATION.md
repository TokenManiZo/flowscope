# 목업 검증 기록

검증일: 2026-10-05. 대상은 `docs/feedback-ui-mockup/`의 합성 목업이다.

## 목업 브라우저 검증

설치된 Google Chrome을 Playwright로 실행해 다음 동작을 확인했다. 브라우저 JavaScript 오류는 없었다.

- 세 화면 전환, 관측 기록 선택, 검색 결과 없음과 조건 복구.
- 원문 글자 크기 변경, 줄바꿈, 확대와 Esc 복귀.
- 키보드로 요청·응답 경계 너비 조절.
- API 행의 버튼 외 영역 클릭으로 상세 열기, 미관측 설명, 연결된 관측 기록 표시.
- API 미관측 필터에서 4개 후보 표시, 전체 필터 복귀.
- 그래프 확대와 전체 맞춤, 미니맵 접기·다시 펼치기, 출처 필터 초기화.
- 신원 필터가 미니맵에도 반영됨. 모든 출처를 끄면 미니맵에도 노드가 없음.
- 768px에서도 그래프 초기화 버튼이 표시되어 빈 상태에서 조건을 복구할 수 있음.
- API 노드의 Enter 선택, 작은 삭제 확인창, 취소 시 유지.
- 삭제 확정 후 API 표 7→6개, 관측 전체 8→5건, API 노드 3→2개 동기화.
- 이전 삭제 이후 다음 삭제 확인창을 Esc로 닫아도 추가 삭제가 일어나지 않음.
- 새로고침하면 합성 데이터로 초기화.
- 1600×1000, 1280×900, 768×900 캡처. 페이지 자체의 가로 overflow 없음. 표·원문의 내부 스크롤은 허용.

캡처는 [captures/](captures/)에 저장했다. 코드 문법은 `node --check docs/feedback-ui-mockup/mockup.js`로 확인했다.

독립 읽기 전용 디자인 검토는 `ship`으로 마무리됐다. 검토에서 찾은 좁은 화면의 초기화 버튼 숨김과 필터 후 미니맵에 남는 신원 노드를 한 번에 수정했고, 검토자는 두 항목을 해결됨으로 평가했다. 검토자는 캡처·소스·설명서를 확인했으며 브라우저 실행·제품 테스트를 직접 수행한 것은 아니다.

## 최초 세 화면 목업의 제품 자동 검증

저장소 루트에서 `mvn clean verify`를 실행했다. 첫 샌드박스 실행은 테스트용 localhost 서버 생성에서 `Operation not permitted`로 실패했다. 로컬 소켓을 허용한 환경에서 같은 명령으로 다시 실행했다.

- TypeScript 타입 검사와 프론트엔드 빌드 완료.
- 프론트엔드 테스트: 86개 파일, 715개 테스트 통과.
- Java 테스트: 817개 중 813개 통과, 실패·오류 0, 건너뜀 4.
- **전체 빌드는 실패:** 마지막 `maven-shade-plugin:3.6.0` 단계에서 `Could not replace original artifact with shaded artifact`가 발생했다. 이 원인은 별도로 확정하지 않았다. 제품 코드나 빌드 설정을 목업 작업에 섞어 변경하지 않았다.
- 성공한 전체 패키징이나 실제 Burp 검증으로 보고하지 않는다.

## 검증하지 않은 범위

실제 Burp UI, 실제 대상 HTTP 요청, 실제 프로젝트 파일 삭제·저장, 큰 실제 데이터셋의 그래프 성능, 트랙패드의 native pinch, macOS 외 OS, archive·human audit 참조가 있는 데이터의 삭제 방어는 검증하지 않았다. 이 목업은 해당 서버 계약을 구현하지 않는다.

`graphify update .`를 실행해 코드 그래프를 갱신했다. AST 갱신이며 문서·이미지의 의미 추출은 수행하지 않았다. 당시 갱신은 7,485개 노드·250개 커뮤니티로 재구성되어 집계 HTML을 생성했다. 기존 커뮤니티 이름은 별도의 재라벨링 대상이라는 도구 안내가 있었다.

## API 강조 추가 검증

2026-10-05에 강조 기능을 추가한 합성 목업을 설치된 Google Chrome과 Playwright로 실행했다. 위 최초 목업 검증과 구분하며, 제품의 강조 저장·Burp 동기화를 검증한 것은 아니다.

- 9색 팝오버, 현재 색 체크·이름, 형광펜 버튼과 API 노드 우클릭 진입.
- 색 지정·해제가 즉시 카드 배경, 상세 색 이름, 비교표 행, 미니맵 API에 반영됨.
- 그래프와 API 표의 강조 필터, 강조 해제 후 결과 수 감소, 모두 해제한 빈 상태 복구.
- 필터·배치 초기화 후에도 색 유지, API 삭제 후 해당 강조 제거.
- 형광펜과 팔레트의 Enter 조작, Esc 닫기, 미지정 API의 해제 비활성화.
- 페이지 새로고침 시 기본 합성 강조 예시로 복귀.
- 1600px 캡처와 1280·768·390px에서 팔레트가 viewport 안에 놓임. 색 이름과 체크 표시를 확인함.
- 브라우저 JavaScript 오류 없음. `node --check`와 `git diff --check` 통과.

강조 캡처는 `captures/highlight-*.png`에 저장했다. 기존 선택 테두리와 출처·HTTP 상태 색상은 캡처와 코드로 확인했다.

독립 읽기 전용 디자인 검토는 `ship`으로 마무리됐고, 강조 추가 범위에서 중요한 문제는 발견되지 않았다. 검토자는 6개 캡처와 관련 소스·설명서를 확인했으며 브라우저 조작이나 제품 테스트를 직접 실행하지 않았다. 실제 프로젝트 저장과 다른 브라우저는 검증하지 않았다.

저장소 루트에서 `mvn clean verify`를 다시 실행해 **BUILD SUCCESS**를 확인했다. TypeScript 검사·프론트엔드 빌드, 프론트엔드 86개 파일·717개 테스트, Java 817개 테스트(실패·오류 0, 건너뜀 4), 배포 번들 생성과 release JAR 검증까지 완료됐다. 현재 작업 트리에는 별도 작업의 변경도 포함되어 있으므로 이 결과는 해당 시점 전체 작업 트리의 자동 검증이다. 실제 Burp 실행 검증은 아니다.

강조 추가 후 `graphify update .`도 완료했다(7,561개 노드·270개 커뮤니티). AST 갱신이며 문서·이미지 의미 추출이나 커뮤니티 재라벨링은 수행하지 않았다.

## API 보안 검토 추가 검증

2026-10-05, 설치된 Google Chrome과 Playwright로 합성 검토 항목의 동작을 확인했다. 실제 취약점 탐지·제품 프로젝트 저장을 검증한 결과는 아니다.

- 그래프·API 상세의 보안 검토 버튼과 배지에서 동일한 패널 열기.
- 항목 등록·변경, 검토 필요·확인됨·오탐별 개수와 그래프·표 필터 동기화.
- 확인 저장에 근거·판단 이유를 요구함. BOLA/BFLA 정책 누락 시 저장 비활성화. 미관측 API는 후보 등록만 가능함.
- 오탐 변경 후 활성 배지에서 제외되고 이전 상태·근거는 변경 이력에 남음.
- 강조색을 바꿔도 검토 상태·배지가 유지됨. 필터 초기화 후 검토 항목 보존.
- 근거를 참조하는 API 삭제 차단, 참조가 없는 설정 API의 관측 포함 삭제 성공.
- 근거의 보기 버튼으로 해당 관측 화면 이동. Esc 닫기·초안 취소·그래프 배지의 Enter 진입.
- 1600px 캡처와 1280·768·390px에서 검토 패널의 viewport 경계 확인. 패널 내부 스크롤로 하단 필드·저장 버튼 접근.
- 브라우저 JavaScript 오류 없음. `node --check`와 `git diff --check` 통과.

최초 브라우저 검사에서 삭제 직후 개수 검사가 비동기 dialog close보다 먼저 실행되어 실패했다. 실제 삭제 완료를 기다리도록 검사 코드를 수정한 재실행은 전체 통과했다. 목업 삭제 구현을 이 검사 때문에 변경하지 않았다.

캡처는 `captures/security-*.png`에 저장했고 모든 파일을 열어 해당 화면과 내용이 표시되는지 확인했다. 디자인 감지기는 한 번 실행했다. 기존 팝오버·삭제창·토스트와 새 패널의 테두리+넓은 그림자, 그래프 배경 격자에 advisory를 보고했다. 새 패널은 그림자를 제거하고 테두리를 유지했다. 나머지는 기존 범위와 실제 그래프 캔버스로, 전역 변경하지 않았다.

추가로 작은 화면의 패널을 끝까지 스크롤해 저장 버튼이 패널 안에 놓이는지 확인했다. BFLA의 정책 누락 검사와 현재 항목에서 근거를 해제해도 이전 변경에 남은 근거가 삭제를 차단하는 동작도 통과했다.

독립 디자인 검토의 첫 결과는 `fix`였다. 정확한 진입 배지로 초점이 돌아가지 않는 문제를 지적했고, 그래프 배지의 포인터 입력이 이동 핸들러에 잡힐 가능성을 제시했다. 실제 Chrome 클릭으로 후자를 재현했다. 지역·API·배지 상태를 포함한 안정적인 진입 ID, 배지 소멸 시 복귀 대상, 패널이 열린 경우만 초점 복귀, 그래프 배지의 pan 제외를 한 번에 수정했다.

수정 후 Chrome에서 그래프의 후보·확인 배지 실제 클릭, 그래프·표·양쪽 상세 패널의 정확한 진입점 복귀, 원래 배지 소멸 시 검토 버튼 복귀, 화면 전환 시 탐색 버튼 초점 유지, 키보드로 강조 팔레트 열 때 검토 패널 닫기를 확인했다. 오류는 없었다. 첫 수정 검사는 패널 뒤에 가려진 형광펜을 마우스로 클릭하려다 timeout이 발생해, 접근 가능한 비모달 키보드 경로로 검사한 재실행이 통과했다.

검토자는 후속 소스 검토에서 두 상호작용 수정을 모두 해결됨으로 평가하고 `ship`을 반환했다. 검토자는 8개 캡처·관련 소스·설명서를 읽었으며 브라우저와 제품 테스트를 직접 실행하지 않았다. 상호작용만 바뀌어 재캡처는 필요 없다고 평가했다.

저장소 루트의 `mvn clean verify`는 **BUILD SUCCESS**였다. TypeScript 검사·프론트엔드 빌드, 프론트엔드 87개 파일·725개 테스트, Java 823개 테스트(실패·오류 0, 건너뜀 4), 배포 번들과 release JAR 검증이 완료됐다. 이 실행은 마지막 포인터·초점 수정 전이며, 해당 수정은 별도 Chrome 검사와 문법 검사로 검증했다. 제품 코드는 변경하지 않았다. 별도 작업의 변경이 포함된 당시 전체 작업 트리 결과이며, 실제 Burp 실행 검증은 아니다.

마지막 상호작용 수정 후 `graphify update .` 완료: 7,603개 노드·261개 커뮤니티. AST 갱신이며 문서·이미지 의미 추출과 커뮤니티 재라벨링은 수행하지 않았다.

독립 문서 검토는 기존 목업 시스템 유지와 설명서의 정확성을 확인했다. 합성 메모리 동작과 향후 프로젝트 저장을 구분하며 중요한 불일치가 없다고 평가했다. 제품의 OKLCH/Geist와 목업의 hex/system font 차이는 기존 차이로 보고했고, 시스템 파일을 수정하지 않았다. 검토자는 브라우저·제품 테스트를 실행하지 않았다.
