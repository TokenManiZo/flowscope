# 1단계: 배치 유지와 프로젝트 저장 목업

- 기준: 업데이트된 `QA_TEMP` (`8bc618f`, 2026-10-03 원격 조회 기준). 목업 커밋을 최신 기준 위로 rebase했다.
- 브랜치: `FEAT/graph-stage-01`. 현재 로컬 저장소와 Git 브랜치를 공유하는 별도 worktree에서 작업한다. 후속 기능·수정 브랜치에도 `FEAT`, `FIX` 등 작업 종류를 사용하며 `codex/` 접두사는 사용하지 않는다.
- 상태: **목업 피드백·승인 대기. 제품 기능 개발 전.**
- UI 대상: 데스크톱. 모바일은 이번 작업에서 제외한다.
- 빌드·단위 테스트·기능 검증은 사용자가 수행한다. 이 단계에서 Maven 빌드나 자동 기능 테스트는 실행하지 않았다.

## 미리보기

현재 로컬 미리보기: <http://127.0.0.1:18847/docs/graph-stage-01/index.html?mode=proposed#graph>

기존 프런트엔드 의존성이 설치된 환경에서, 저장소 루트에서 실행한다.

```sh
[ -e node_modules ] || ln -s frontend/node_modules node_modules
node frontend/node_modules/vite/bin/vite.js --config docs/graph-stage-01/vite.config.mjs --configLoader native
```

이 작업 공간에서는 이미 설치된 프런트엔드 의존성을 로컬 symlink로 연결했다. 의존성 연결과 Vite 캐시는 커밋하지 않는다. 제품 소스·프로젝트 DB를 수정하지 않고, 기존 샘플 fixture와 카드 렌더러·화면 셸을 재사용한다.

상단 검토 바는 목업을 조작하기 위한 별도 도구다. `프로젝트 A/B`, `프로젝트 다시 열기`, `신규 노드 추가`, `예시 초기화`는 실제 제품 서버 작업을 실행하지 않는다. 모든 API 응답은 합성 예시이며 변경 요청은 차단한다.

## 피드백할 동작

1. API 카드를 이동하거나 오른쪽 아래 모서리로 크기를 변경한다.
2. 왼쪽 `계정·세션` 화면에 갔다가 그래프로 돌아온다.
3. `Site Overview`로 이동한 뒤 ORDERS 그룹을 더블클릭한다. API를 더블클릭하면 객체 보기로 이동한다.
4. `목록`과 `그래프` 보기를 전환한다.
5. `프로젝트 다시 열기` 또는 브라우저 새로고침으로 배치를 다시 읽는다.
6. 프로젝트 A와 B를 전환해 같은 노드의 서로 다른 배치를 확인한다.
7. API 그룹 보기에서 `신규 노드 추가`를 누른다. 기존 노드 좌표와 viewport는 유지하고 신규 노드만 추가한다.
8. `화면에 맞추기`와 `레인 기준 정렬`을 비교한다. 전자는 viewport만, 후자는 배치만 변경한다. 카드 크기는 유지한다.
9. `위치 잠금`과 자동 묶음 펼침·접힘을 확인한다.

`현행 QA_TEMP`는 같은 fixture로 수정하지 않은 실제 App을 연다. 현행 동작 비교 시 같은 레인의 노드를 겹치게 옮긴 뒤 다른 화면으로 이동했다가 돌아오는 흐름을 직접 확인할 수 있다. 이 회귀의 실제 런타임 재현·기능 판정은 아직 수행하지 않았다.

## 승인할 설계

- 프로젝트마다 사이트·API 그룹·개별 API 보기의 배치와 viewport를 독립적으로 보존한다.
- 화면에 잠시 표시되지 않는 노드의 위치·크기도 보관한다.
- 저장 좌표의 겹침을 자동으로 풀지 않는다. 새 노드만 기존 배치 아래의 빈 영역에 배치한다.
- 화면 크기·테마·상세 패널 변경은 모델 좌표를 바꾸지 않는다.
- `화면에 맞추기`는 pan/zoom만, 명시적 `레인 기준 정렬`은 위치만 바꾼다. 정렬 시 카드 크기를 초기화하지 않는다.
- 자동 의미 묶음을 펼칠 때 기존 노드는 유지하고 새로 보이는 멤버만 배치한다.
- 계속 하나의 전역 배치를 덮어쓰는 방식과 화면 복귀 시 전체 자동 정렬 방식은 사용자 배치가 사라지므로 채택하지 않는다.

## 제품 개발 시 연결할 부분

목업의 브라우저 저장은 프로젝트 저장을 설명하는 시뮬레이션이다. SQLite·JSON, checkpoint, 구버전 프로젝트 호환, 기존 브라우저 배치의 이관과 서버 workspace revision은 **승인 후 1단계 제품 개발 범위**다.

소스에서 확인한 원인 경로:

- `CytoscapeGraph.positionInLanes()`는 저장 위치 복원 후 `separateLaneNodes()`로 좌표를 보정한다.
- `RelationshipGraphView.updatePreferences()`는 현재 화면의 위치로 저장 맵을 교체한다.
- `graphPreferences`는 프로젝트·계층 구분 없이 하나의 localStorage 키를 사용한다.
- projection·테마 등 변경 시 그래프 요소를 제거하고 다시 만드는 effect가 있다.

선택·Evidence·정책은 제품 개발에서도 기존 의미를 유지한다. 검색·노드 색 표시·다중 선택·이동 묶음·Request Lab 개편·삭제는 이 목업과 구현 범위에 포함하지 않는다.
