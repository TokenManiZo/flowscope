## 구현한 동작과 설계 선택

프로젝트의 `graphWorkspace`에 사이트·서비스/API 그룹·개별 API 보기별 노드 위치·크기, viewport와 자동 묶음 펼침 상태를 저장한다. 마지막 계층과 표시 개수, 위치 잠금, 입력 모드도 프로젝트에 보존한다. 검색어·선택·드래그 상태는 추가하거나 저장하지 않는다.

저장 위치를 복원한 뒤 실행되던 자동 겹침 해소를 제거했다. 사용자가 겹쳐 놓은 노드도 그대로 복원하며 새 노드만 기존 노드 아래에 배치한다. 현재 표시된 노드의 좌표를 기존 저장 맵에 합쳐 접힘·18개 표시 제한 밖의 좌표를 보존한다. 화면 복귀·계층 왕복·테마 변경·상세 패널 크기 변경으로 모델 좌표를 정렬하지 않는다.

레인 제목 클릭은 해당 레인만 정렬한다. 기존 필터의 `레인 기준 재정렬` 버튼은 유지하며 새 정렬 버튼은 추가하지 않는다. 정렬은 위치만 변경하고 카드 크기·viewport를 유지한다. 화면 맞추기는 viewport만 변경한다. 기존 `초기화`는 현재 보기의 좌표·크기·펼침 상태를 초기화한다.

서버 API의 배치 revision과 데이터 교체 revision을 함께 확인해 다른 프로젝트나 다른 창의 오래된 저장을 거부한다. 프로젝트 전환 요청 전에 진행 중인 배치 전송을 기다린다. 저장 실패 시 현재 배치를 화면에 남기고 오류를 표시한다. `저장된 배치 다시 불러오기`를 선택하면 미저장 변경을 버리고 서버 상태를 읽는다.

JSON 프로젝트 schema는 7이며 1~6을 읽는다. SQLite 테이블 schema는 3을 유지하고 선택적 metadata만 추가한다. 새 필드가 없는 프로젝트는 빈 workspace로 읽는다. 기존 브라우저 전역 배치는 처음 열린 빈 workspace에 한 번 이관하고 서버가 수락한 뒤 이전 키를 제거한다. 전역 배치의 과거 소속 프로젝트는 알 수 없으므로 여러 프로젝트에 복제하지 않는다.

## 성능 고려

- 드래그 종료·크기 조절 종료에 위치를 캡처하고, viewport 갱신은 animation frame 단위로 합친다.
- 동일한 좌표·크기는 기존 객체를 유지한다. 전체 workspace를 매번 JSON 문자열로 비교하지 않는다.
- 연속 변경은 250ms 모아 변경된 보기·설정만 전송한다. 저장 응답은 revision만 반환한다.
- Burp에서는 기존 30초 checkpoint로 디스크 쓰기를 합친다. 트래픽 revision이 같으면 SQLite metadata만 트랜잭션으로 저장한다. 전체 트래픽·payload 인코딩과 재분석을 유발하지 않는다.
- Standalone의 즉시 저장 경로도 배치만 변경할 때 metadata만 저장한다.

보기 하나의 변경은 해당 보기 전체를 직렬화하고, SQLite metadata checkpoint는 전체 workspace를 직렬화한다. 노드가 많으면 그 비용은 늘어난다. 현재 상한은 프로젝트당 200개 보기, 보기별 저장 좌표의 합 20,000개이며 API 변경 JSON은 2MiB다. 상한 초과는 오류로 표시하고 임의로 기존 좌표를 삭제하지 않는다. 실제 지연·메모리 사용·저장 시간은 측정하지 않았다. 더 세밀한 노드별 패치나 별도 좌표 테이블은 측정 결과가 필요할 때 검토한다.

## 사용자가 진행할 검증

빌드·단위 테스트·기능 검증은 사용자가 수행한다. 이 구현에서 Maven·프런트엔드 빌드, 테스트 실행, Playwright 제스처 검증, DB 저장 실험, 성능 benchmark를 실행하지 않았다.

추가·수정한 회귀 테스트는 좌표 겹침 복원, 신규 노드 배치, 숨긴 노드 보존, 보기 구분, 정렬 시 크기·viewport 유지, 전송 직렬화, stale revision 거부, 전환 전 flush, JSON·SQLite 호환과 metadata checkpoint를 다룬다. Standalone의 프로젝트 전환·재열기·초기화도 테스트 코드에 포함했다. 테스트 통과 여부는 미확인이다.

1. 원본 프로젝트 루트(`/Users/gwangwon/development/flow/flowscope`)에서 `mvn clean verify`를 실행한다.
2. 제품에서 노드를 일부 겹쳐 이동·크기 변경한 뒤 계정 화면 왕복, 계층 왕복, 목록 왕복을 확인한다.
3. 레인 제목 정렬과 필터 전체 정렬이 크기·viewport를 유지하는지 확인한다.
4. snapshot 갱신·신규 노드·자동 묶음 접힘·펼침에서 기존 모델 좌표를 비교한다.
5. checkpoint 이후 프로젝트를 다시 열고, DB·JSON 내보내기/가져오기와 구버전 프로젝트를 확인한다.
6. 프로젝트 A/B를 전환하고 여러 창의 오래된 저장 거부·오류 후 다시 불러오기를 확인한다.
7. 라이트·다크, 1280/1920px 및 Burp 실물에서 확인한다. Mac·Windows 입력 검증은 별도로 기록한다.
8. 큰 프로젝트에서 이동/팬의 반응, 배치 저장 시간, 전체 checkpoint 횟수와 메모리 사용을 확인한다.
