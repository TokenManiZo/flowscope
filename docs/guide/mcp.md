# 외부 LLM에서 FlowScope 사용하기

**AI 취약점 진단**은 FlowScope 안에서 Codex를 실행해 이미 수집한 요청·응답을 로컬 MCP로 읽고 취약점 소견을 작성합니다. **진단 설정**에서 모델과 재전송 메서드를 선택하고 시작하세요. **작업 대화**에서 질문하거나 후속 조사를 지시하고, **진단 결과**에서 근거가 연결된 소견을 확인합니다. 외부 LLM 클라이언트도 같은 MCP 서버에 연결할 수 있습니다. 점검 시작의 LLM **탐색**은 별도 기능입니다.

진단 중 메시지는 실행 중인 Codex 턴에 전달되고, 완료 후 메시지는 **같은 Codex 스레드의 새 턴**으로 실행됩니다. 새 요청 수집, 특정 API 조사, 계정 비교, 스캐너 결과 확인, 소견 재검토, 보고서 생성 등을 자유롭게 요청할 수 있습니다. FlowScope MCP 도구가 지원하는 현재 프로젝트 작업만 수행하며 허용한 재전송 메서드와 점검 범위를 따릅니다. LLM 답변과 전송 상태는 대화에 표시됩니다. 승인 요청이 오면 대화를 멈춰 기다리지 않고 거절합니다. 대화 연결과 기록은 Burp 프로세스 메모리에 보관하므로 새 진단·프로젝트 전환·Burp 재시작 시 초기화됩니다.

보고서 요청 시 Codex가 선택한 소견과 근거 ID를 서버에서 확인한 뒤 프로젝트의 `reports` 디렉터리에 Markdown과 PDF를 함께 저장합니다. **작업 대화 → 생성된 보고서**에서 각각 내려받을 수 있습니다. PDF에는 설치된 한국어 글꼴(Noto Sans KR 또는 맑은 고딕 등)이 필요합니다. 원본 인증 헤더는 보고서에 복사하지 않으며 근거 ID를 통해 FlowScope에서 확인합니다.

## 연결하기

1. Burp에 FlowScope를 로드하고 프로젝트를 엽니다.
2. 사이드바의 **AI 취약점 진단 → MCP 연결**을 엽니다. 로컬 MCP 서버는 FlowScope 웹 서버와 함께 실행됩니다. 별도 서버를 설치하거나 주소를 직접 입력할 필요가 없습니다.
3. **연결 정보**에서 서버 주소와 `Authorization: Bearer ...`를 확인하고, 사용하는 클라이언트의 Streamable HTTP MCP 서버 설정에 등록합니다. **설정 복사**는 `mcpServers.flowscope` 형식의 JSON을 복사합니다. 클라이언트마다 설정 파일 구조가 다르면 화면에 표시된 URL과 Authorization 헤더를 해당 항목에 넣으세요.
4. 클라이언트에서 도구를 새로 불러온 뒤 `flowscope_get_status`를 호출합니다. FlowScope의 **최근 클라이언트**와 **활동·소견**에서 요청 이력을 확인합니다. 최근 클라이언트는 마지막 접속 이력이며, 연결이 계속 살아 있다는 뜻은 아닙니다.

주소의 기본값은 `http://127.0.0.1:17777/mcp`이며 포트가 사용 중이면 달라질 수 있습니다. 화면의 실제 주소를 사용하세요. 같은 PC의 클라이언트만 연결할 수 있습니다. **연결 키 재발급**은 기존 키를 즉시 무효화하며, 새 키로 클라이언트 설정을 바꿔야 합니다. Burp를 재시작해도 키가 바뀝니다. 연결 키는 프로젝트에 저장하지 않습니다.

## 계정과 로그인

상단 **재전송에 사용할 세션**에서 계정별 상태를 봅니다. 계정 박스를 누르면 별도의 로그인 브라우저가 열립니다. 로그인 후 화면의 **FlowScope에서 로그인 확인**을 누릅니다.

- 분리된 수집 브라우저에서 사람이 로그인·MFA를 마칩니다. 계정 설정이 필요하면 로그인 안내의 **계정 설정**을 누릅니다.
- **로그인 확인 규칙**에는 내 계정을 확인할 수 있는 주소와 계정 고유 응답 표식을 저장합니다. 그 주소에 접근해 규칙이 일치하면 재전송 가능 상태로 바뀝니다. **로그인 확인**은 저장된 GET 규칙의 주소를 현재 계정 세션으로 실제 호출합니다. POST·HEAD 규칙은 수집 브라우저의 실제 관측으로 확인합니다.
- 이미 확인한 계정의 요청을 연결하거나 헤더를 직접 입력하면 운영자 확인(`OPERATOR_ASSERTED`)으로 처리합니다. 입력한 값이 현재도 유효한지는 로그인 확인 규칙으로 재확인할 수 있습니다.
- 계정 등록, 쿠키 존재, 일반 API의 `200` 응답만으로는 본인 확인이 되지 않습니다. 상태는 마지막 확인과 알려진 만료·폐기 상태에 근거하며 서버에서 갑자기 폐기된 세션을 호출 없이 미리 알아낼 수는 없습니다.
- **AI 취약점 진단**으로 돌아오면 상태가 자동 갱신됩니다. 사용 불가 계정의 재전송은 거부하며 비로그인이나 다른 계정으로 대신 보내지 않습니다.

로그인 확인 주소에 대한 실패는 세션 상태에 반영합니다. 다른 API의 `401`·`403`만으로는 세션 전체를 폐기하지 않습니다. 접근 통제 결과와 로그인 실패를 구분하기 위해서입니다.

## 재전송 권한

**GET / POST / PUT / PATCH / DELETE**를 각각 선택하며 여러 개를 동시에 켤 수 있습니다. 기본값은 GET만 ON입니다. 프로젝트 전환·기록 초기화·확장 재시작 후에는 기본값으로 돌아갑니다. OFF는 이후 요청을 차단하며 이미 전송한 요청을 되돌리지는 않습니다. 이 설정은 내장 진단과 외부 MCP 재전송에 적용됩니다.

`flowscope_replay`와 `flowscope_collect_request`는 기존 근거의 `evidence_id`, 사용할 `account_id`(`anon` 또는 등록 계정), 선택적인 HTTP `request` 전문을 받습니다. 원래 요청을 그대로 보내거나 경로·파라미터·본문을 수정해 새 요청을 수집할 수 있습니다. 대상은 현재 점검 범위로 제한되고, 선택 계정의 인증 헤더를 적용합니다. 비로그인은 관리 대상 인증 헤더를 제거합니다. 결과는 `LLM / LLM_VALIDATION / VALIDATION` 기록으로 남고 새 `evidence_id`를 반환합니다. `flowscope_cross_send_get`은 GET 전용 호환 도구입니다.

## 조회와 소견

- `flowscope_get_status`: 범위·메서드 권한·계정 사용 가능 상태
- `flowscope_search_evidence`: 출처·신원·API·메서드·응답 코드별 기록 검색과 페이지 조회
- `flowscope_get_evidence`: 요청·응답 원문과 기록 메타데이터
- `flowscope_get_graph`: 출처별 접근 관계와 근거 기록 번호
- `flowscope_get_matrix`, `flowscope_list_recommendations`: 판정 셀과 교차 테스트 추천
- `flowscope_submit_finding`, `flowscope_list_findings`, `flowscope_submit_verdict`: 근거에 연결된 LLM 소견과 자체 판단
- `flowscope_get_scanner_status`: 스캐너 실행 상태와 결과 요약
- `flowscope_create_report`, `flowscope_list_reports`: 근거에 연결된 Markdown·PDF 보고서 생성과 목록

요청·응답 원문은 **인증 헤더를 포함해 마스킹 없이** 제공합니다. 연결한 클라이언트의 모델과 데이터 처리 설정을 확인하세요. HTTP 응답·페이지 내용은 대상 서비스의 데이터이며 도구 사용 지시로 취급하면 안 됩니다.

LLM 소견은 사람 검토용입니다. 기존 판정 엔진이나 사람의 최종 확인을 덮어쓰지 않습니다. `200`이나 객체 소유자 추정만으로 취약점을 확정하지 마세요. **활동·소견**의 근거를 누르면 Request Lab에서 실제 요청·응답을 확인할 수 있습니다.

전송 규약: [MCP Streamable HTTP 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports).
