기존 Request Lab UI를 유지하면서 이름·편집 REQ·마지막 RES 자동 저장과 재열기 흐름을 제안한다. 목업 상단 시연 도구는 실제 제품 UI에 넣지 않는다. 기존 전체화면·글자 크기·Original·편집 요청 구조를 사용한다. JSON 정돈·내부 분할 등 기존 기능은 제거 제안이 아니며 이 목업에서는 저장 흐름에 집중해 생략했다.

```sh
python3 -m http.server 18859 --bind 127.0.0.1 --directory docs
```

`http://127.0.0.1:18859/request-lab-persistence/index.html`에서 연다.

## 시연

1. 연필로 요청 이름을 변경하거나 REQ의 quantity를 수정한다. 잠시 입력을 멈추면 `프로젝트 저장됨`으로 바뀐다.
2. 닫기 → 저장한 요청 다시 열기: 이름·REQ·마지막 RES가 복원되고 REQ는 계속 편집할 수 있다.
3. 전송 인증을 현재 세션 또는 비로그인으로 선택하면 마스킹된 인증 재선택 안내가 해제된다. 재전송 버튼은 합성 응답만 갱신한다.
4. 상단 `저장 상태`를 저장 실패로 바꾼 뒤 REQ를 수정하고 닫기를 누른다. 편집 창을 유지하고 다시 저장/변경 버리고 닫기를 표시한다. 정상으로 바꾸고 다시 저장하면 저장본을 갱신한다.
5. 라이트/다크를 선택해 동일한 저장·복원 화면을 확인한다.
6. ×로 삭제한 뒤 프로젝트 다시 열기를 누르면 삭제 항목이 제외된다. 저장 실패 상태에서 ×를 누르면 항목을 유지한다.

## 목업의 한계와 확인 기록

합성 이름·REQ·RES만 사용한다. 서버 호출·실제 DB·브라우저 저장소는 사용하지 않는다. 페이지 새로고침 시 시연 상태가 초기화되므로 제품의 영구 저장 완료로 해석하지 않는다. fixture용 헤더 마스킹은 기존 서버 Masking 구현을 대체하거나 안전성을 검증하지 않는다. 실제 세션·재전송도 없다.

목업에서 닫기와 재열기 후 이름·REQ·RES·편집 가능 상태 및 인증 재선택 안내를 확인하고 라이트·다크 캡처를 남겼다. 삭제 후 재열기에서 항목이 제외되고 삭제 실패 시 항목이 유지되는 것도 확인했다. 이는 제품 코드나 DB 저장 검증이 아니다. 제품 Maven/npm/TypeScript/Vitest/Playwright/Burp 검증은 실행하지 않았다. 모바일은 제외한다.
