# 계정별 세션 격리와 검증

같은 브라우저에서 A를 로그아웃하고 B로 로그인해도 Cookie, localStorage, IndexedDB 같은 상태가 남을 수 있습니다. 계정마다 독립된 브라우저로 점검하고, 실제 로그인한 계정과 FlowScope에서 선택한 계정이 일치하는지 확인하세요.

## 계정별로 점검하기

1. **계정·세션**에서 비교할 테스트 계정을 등록합니다.
2. 해당 계정의 **시작**을 눌러 FlowScope가 여는 전용 브라우저에서 로그인합니다. HUMAN 수집은 계정별 브라우저와 프록시 리스너를 사용합니다.
3. 로그인한 계정으로 기능을 둘러봅니다. 수집 중에는 선택한 계정이 요청 귀속의 기준이며, 계정 전환을 자동으로 감지하지 않습니다.
4. 다른 계정으로 로그인하려면 먼저 현재 수집을 **종료**하고, 다른 계정의 **시작**을 누릅니다. **일시 정지**는 브라우저 상태를 유지하므로 계정 전환용으로 사용하지 않습니다.

ZAP 로그인 설정과 LLM의 브라우저 로그인도 같은 등록 계정에 연결합니다. LLM 로그인은 FlowScope가 연 별도 Chromium 창에서 직접 수행합니다. 전체 순서는 [점검 흐름 상세](guide/inspection-flow.md)를 참고하세요.

## 세션 연결과 신원 확인

등록 계정, 관측 요청의 인증 지문, 재전송에 쓰는 세션은 서로 다른 정보입니다. 쿠키나 토큰이 있다는 사실만으로 로그인 성공이나 계정 소유가 증명되지는 않습니다. 등록 계정의 이름·역할과 데이터 소유자는 사용자가 확인해야 합니다.

확인한 Burp 요청을 수동 연결할 때는 **FlowScope 계정 세션으로 사용**에서 계정을 지정합니다. 응답의 사용자명처럼 로그인 성공을 확인할 표식을 선택적으로 입력할 수 있습니다. 쿠키·토큰·비밀번호를 성공 표식으로 넣지 마세요.

| 검증 출처 | 의미 |
|---|---|
| 운영자 확인 | 사용자가 확인한 Burp 교환을 계정에 직접 연결 |
| 규칙 확인 | 저장된 검증 URL과 로그인 성공 표식이 응답에서 모두 일치 |
| 약검증 | 명시적인 성공 표식 없이 HTTP 응답으로 연결된 하위호환 세션 |
| 미검증 | 세션 검증 근거 없음 |

능동 교차 신원 재전송은 **운영자 확인·규칙 확인** 세션만 사용합니다. 약검증 세션은 Request Lab에서 하위호환으로 사용할 수 있지만, 로그인한 계정이 맞는지 직접 확인해야 합니다.

## 로그인 문제 확인하기

- 로그인 실패 페이지도 `200`을 반환할 수 있습니다. 상태 코드만 보지 말고 응답의 계정 정보와 로그인 상태를 확인하세요.
- 검증 규칙의 성공 표식은 본문에 문자열이 포함되는지 검사합니다. 다른 화면에도 나타나는 흔한 문구를 피하세요.
- ZAP의 로그인 결과는 관측된 요청·응답과 함께 확인합니다. 로그인 성공 표식을 설정했다면 그 표식의 일치가 필요합니다.
- 인증값 만료나 로그인 화면으로의 이동이 나타나면 해당 계정으로 다시 로그인하세요. CAPTCHA, MFA, WebAuthn은 수동 조작이 필요할 수 있습니다.
- 외부 브라우저를 직접 사용하는 경우 계정마다 별도 프로필을 사용하세요. HTTP 프록시만으로는 브라우저 내부 저장소를 격리할 수 없습니다.

## 저장과 보호

FlowScope의 재사용 Cookie·Authorization은 현재 프로세스 메모리에서만 보관합니다. 프로젝트·내보내기·Evidence에는 비밀값을 마스킹하며, 브라우저와 ZAP의 일시 상태는 각 실행 환경에서 관리됩니다.

마스킹된 프로젝트에도 대상 경로·식별자·응답 데이터가 남을 수 있습니다. 실제 점검 기록을 GitHub에 올리지 마세요. 데이터 처리 범위와 한계는 [판정 규칙·데이터 처리·한계](reference/trust-and-limits.md)를 참고하세요.
