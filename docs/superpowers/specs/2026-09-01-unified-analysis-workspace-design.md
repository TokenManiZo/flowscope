# FlowScope 통합 분석 워크스페이스 디자인

> **과거 UI 설계 / 현재 상태 아님.** 아래는 2026-09-01 승인 범위의 기록이다. D-126에서 기존 LLM 실행·Judge·MCP 제어를 제거했으므로 당시의 전체 동작 보존을 이유로 복원하지 않는다. 현행 설명은 [UI 근거](../../ko/ui-product-rationale.md), 진행상황은 [HANDOFF](../../ko/HANDOFF.md)를 따른다.

작성일: 2026-09-01

## 목표

FlowScope의 React/shadcn UI를 90% 정보 밀도의 상단 내비게이션 기반 분석 워크스페이스로 통합한다. 공격면 그래프는 제공된 세 번째 참고 이미지의 정보 구조를 재현하고, 권한 매트릭스·흐름 순서·취약점 시나리오·Request Lab은 같은 색 체계와 상세 패널 패턴을 사용한다. 기존 서버 판단과 API 동작은 변경하지 않는다.

## 범위

- 전역 사이드바를 상단 내비게이션과 보조 컨텍스트 바로 교체한다.
- React UI의 기본 밀도를 현재 대비 90%로 조정한다.
- 공격면 그래프를 좌측 필터, 중앙 3열 그래프, 우측 선택 상세 패널 구조로 변경한다.
- 권한 매트릭스의 판정, 소스, 갭과 충돌을 색과 공간으로 구분한다.
- 흐름 순서를 신원별 타임라인으로 변경한다.
- 취약점 시나리오를 후보 목록과 선택 상세의 분할 작업면으로 변경한다.
- Request Lab을 데스크톱 2열 작업면과 모바일 단일 열로 재구성한다.
- 분석 화면의 `이전 snapshot을 표시 중입니다.` 문구를 제거한다.
- Burp가 여는 `/`에서 React UI를 제공하고 기존 UI는 `/legacy/`에 보존한다.

LLM Explorer/Judge 실행 자체의 문제는 이번 범위에 포함하지 않는다.

## 공통 워크스페이스 셸

### 상단 내비게이션

첫 번째 행은 약 52px 높이로 구성한다.

- 좌측: 잘리지 않는 FlowScope 심볼, 제품명, `ACCESS ANALYSIS` 보조 라벨
- 중앙: 빠른 시작, 분석 대시보드, 실행 기록
- 우측: 점검 준비 상태, Scope 개수, HUMAN/ZAP 상태, 새로고침, 점검 계속

두 번째 행은 약 36px 높이의 컨텍스트 바로 구성한다.

- 현재 Scope 또는 `등록된 범위 없음`
- 현재 데이터셋/Run 상태
- 실시간 수집 상태

전역 사이드바는 제거한다. 기존 세부 경로는 상단 내비게이션의 분석 메뉴와 각 작업면 내부 탭에서 접근한다. 작은 화면에서는 내비게이션을 가로 스크롤 또는 메뉴로 축약하되 로고는 항상 완전히 표시한다.

### 90% 밀도

React 애플리케이션 루트에 공통 밀도 토큰을 적용한다. 흐릿한 CSS transform은 사용하지 않는다.

- 기본 rem 크기, 카드 여백, 버튼 높이, 아이콘, 표 행 높이를 함께 축소한다.
- 본문은 13~14px의 실질 크기를 유지한다.
- 원문 요청·응답과 Evidence ID는 monospace를 유지한다.
- 클릭 대상은 최소 32px, 주요 작업은 최소 36px을 유지한다.

## 공통 색 체계

- 강조/현재 선택: emerald
- HUMAN: blue, solid
- SCANNER/ZAP: red, dashed
- LLM: zinc-200, dotted
- Allow: emerald
- Deny: red
- Suspicious/Review: amber
- Undecided: violet
- Untested/Unobserved: zinc
- 오류: red, 동기화 주의: amber

색만으로 의미를 전달하지 않는다. 모든 색 표현은 텍스트, 아이콘, 선 스타일 또는 배지와 함께 사용한다.

## 공격면 그래프

### 레이아웃

데스크톱은 다음 세 영역을 동시에 표시한다.

1. 좌측 약 220px 필터 레일
2. 중앙 가변 폭 그래프 캔버스
3. 우측 약 360px 선택 상세 패널

좌측 필터는 Source, Identity, Review State, Focus 순서로 배치한다. 각 항목에는 체크박스, 선 스타일, 라벨, 현재 결과 수를 함께 표시한다.

중앙은 `IDENTITY / RESOURCE / OPERATION` 세 열로 나눈다. 상단에는 개수, 확대/축소, 맞춤, 전체 화면 컨트롤을 둔다. 노드는 어두운 카드, 얇은 판정 테두리, 메서드 배지, 짧은 보조 설명을 사용한다.

우측 상세 패널은 선택한 작업의 개요, Evidence, Request, Response 탭과 Access Check 요약을 제공한다. 데스크톱에서는 그래프를 덮는 Sheet가 아니라 레이아웃의 고정 열이다. 작은 화면에서는 Sheet로 전환한다.

### 열 제약

각 노드는 종류에 따라 고정된 lane을 가진다.

- identity 노드: 왼쪽 열
- resource 노드: 가운데 열
- operation 및 route candidate 노드: 오른쪽 열

확대, 축소, 맞춤, 컨테이너 크기 변경 후 lane controller가 각 노드의 화면상 X 좌표를 해당 열의 안전 영역으로 재투영한다. 사용자 드래그는 Y축 이동을 허용하되 X축은 현재 lane의 최소·최대 범위로 제한한다. 열 구분선은 동일한 lane 계산값을 사용한다. 따라서 뷰포트가 바뀌어도 노드와 열의 의미가 분리되지 않는다.

키보드 사용자는 항상 API 목록 보기로 같은 데이터를 탐색할 수 있다. Cytoscape 초기화 실패 시 목록 보기로 자동 전환한다.

## 권한 매트릭스

가로 표 구조는 유지하되 정보 계층을 다시 구성한다.

- 첫 신원/역할 열과 상단 작업 헤더는 sticky로 유지한다.
- 작업 헤더는 메서드 배지, 축약 경로, 리소스, 소유자, 필수 역할 순서로 표시한다.
- 셀은 판정별 약한 배경색과 왼쪽 강조선을 가진다.
- 셀 상단에는 전체 판정과 Evidence 열기 작업을 둔다.
- HUMAN, SCANNER, LLM 결과는 각각 한 줄의 소형 source row로 표시한다.
- 충돌, 갭, 미관측은 판정과 분리된 상태 배지로 표시한다.
- 긴 근거는 셀에 반복하지 않고 우측 상세 패널에서 확인한다.

셀 배경색은 낮은 채도로 사용해 큰 표에서도 눈이 피로하지 않게 한다. 텍스트와 배지는 충분한 대비를 유지한다.

## 흐름 순서

신원별 그룹 안에서 생산 요청, 전달된 마스킹 값, 소비 요청을 연결하는 타임라인을 사용한다.

- 순서 번호와 방향선으로 흐름을 명확히 한다.
- source 선 스타일과 색을 함께 표시한다.
- 긴 작업과 값은 초기 상태에서 제한하고 명시적 확장으로 확인한다.
- 선택 시 공통 우측 상세 패널에서 두 endpoint Evidence를 확인한다.

## 취약점 시나리오

데스크톱은 후보 목록과 선택 상세의 2열 구조를 사용한다.

- 좌측: 후보 제목, 유형, 위험도, 검증 상태, Evidence 수
- 우측: 제안, 근거, 검증, 통제 Evidence, 검토 작업
- 위험도와 검증 상태는 공통 의미 색을 사용한다.
- 미리보기와 생성 작업의 기존 서버 계약, 현재 revision 일치 조건, 재시도 동작을 유지한다.

## Snapshot 상태 표시

`isStale`은 데이터가 곧바로 잘못되었다는 뜻이 아니므로 각 작업면에서 `이전 snapshot을 표시 중입니다.`를 렌더링하지 않는다. 기존 데이터는 계속 사용할 수 있다.

- 초기 데이터가 없을 때만 로딩 상태를 표시한다.
- 재요청 실패와 기존 데이터가 함께 있을 때는 상단 상태 영역에 `최근 동기화 오류`만 표시한다.
- 실제 snapshot revision 변경 때문에 사용자 작업을 폐기해야 하는 시나리오 화면의 revision 변경 알림은 유지하되 깜빡이는 stale 문구와 분리한다.

## Request Lab

데스크톱 Dialog는 최대 약 1100px의 2열 구조를 사용한다.

- 좌측: 서비스, 관측 신원, 보존 상태, 문자셋, 자격 증명 모드, 재사용 세션
- 우측: Request/Response 탭, 넓은 monospace 원문 영역, 크기 제한
- 하단: 고정된 닫기와 전송 작업

원문 부재 또는 마스킹 상태는 상단의 작은 상태 배너로 표시한다. 긴 설명문은 줄이고 핵심 제약만 유지한다. 모바일에서는 한 열과 탭 구조로 전환한다. 기존 메모리 전용 보존, 1MiB 제한, 세션 자격 검증, 중복 전송 방지 계약은 유지한다.

## 라우팅과 패키징

`FlowScopeWebServer`의 기본 정적 UI를 React로 설정한다.

- `/`: React UI
- `/app/`: React UI
- `/legacy/`: 기존 UI

Burp의 기존 UI 열기 동작은 `/`를 사용하므로 새 UI가 바로 열린다. React 빌드 산출물은 Maven 리소스 단계 또는 검증된 패키징 단계에서 `web/app`에 포함한다. 오래된 해시 자산이 JAR에 누적되지 않도록 최종 패키징 전에 React 자산 디렉터리를 정리한다.

## 오류 처리와 접근성

- 서버 오류는 페이지의 기존 데이터와 분리해 표시한다.
- 색상에는 텍스트 의미를 병행한다.
- 그래프 목록 보기, 탭, 표 헤더, 상세 패널에 명확한 접근성 이름을 제공한다.
- Evidence ID와 원문은 ARIA label 또는 live region에 넣지 않고 일반 본문에서만 제한·확장한다.
- 키보드로 모든 필터, 셀, 후보, 상세 탭, Request Lab 작업에 접근할 수 있어야 한다.

## 테스트와 완료 조건

### 컴포넌트 테스트

- 상단 내비게이션 경로와 로고 표시
- 90% 밀도 토큰 적용
- 매트릭스 판정별 색/텍스트/source row
- sequence와 scenario의 stale 문구 제거
- Request Lab 데스크톱 2열 및 모바일 구조
- 그래프 목록 전환과 상세 선택

### 그래프 테스트

- 확대/축소 후 identity/resource/operation 노드가 자기 lane에 남는지 검증
- 드래그 후 X 좌표가 lane 범위를 벗어나지 않는지 검증
- 컨테이너 크기 변경과 fit 이후 lane 재투영 검증
- 선 색, 선 스타일, source 텍스트 검증

### 서버 및 패키징 테스트

- `/`와 `/app/`가 React index를 반환
- `/legacy/`가 기존 index를 반환
- React index가 실제 최신 해시 자산을 참조
- 최종 JAR이 해당 자산을 포함

### 실제 브라우저 검증

- 샘플 데이터로 주요 화면의 90% 밀도 확인
- 매트릭스 sticky 헤더와 색 구분 확인
- 그래프 3열, 확대/축소, 선택 상세 확인
- Request Lab의 2열 배치와 반응형 전환 확인
- Burp가 여는 `/`에서 새 UI 확인
