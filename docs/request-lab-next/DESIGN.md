## Request Lab 화면과 동작

**기본 창**은 데스크톱 여백을 두고 약 1152px 폭을 확보한다. 높이는 화면에서 80px 여백을 뺀 범위이며, 기존 좌측 인증 영역은 접힌 상단 상세로 바꾼다. 상단 제목 영역에 전송 인증 방식·계정, 글자 크기, 함께 보기/요청 확대/응답 확대, 인증 상세, 최대화/원래 크기, 기본 크기를 모은다. 별도의 `POST + 주소` 행과 설정 툴바는 제거한다. 대상 method/주소는 Raw와 펼친 인증 상세에서 확인할 수 있게 한다. 이 배치는 사용자가 첨부한 표시 기준을 반영한다.

**브라우저 안 최대화**는 창 바깥 여백만 12px로 줄인다. 브라우저 Fullscreen API를 기본 동작으로 쓰지 않으며 Esc와 닫기를 분리한다. 확대 상태에서 Esc는 먼저 기본 창으로 복귀하고, 기본 창에서의 닫기는 기존 흐름을 따른다. 브라우저/OS 전체 화면은 이번 범위에 추가하지 않는다.

Radix Dialog의 기본 Esc 닫기보다 앞에서 확대 복귀를 처리해야 한다. 이미 JSON 보기나 하위 선택기가 Esc를 처리한 경우는 중복 처리하지 않는다. 편집기를 다른 컨테이너로 옮기는 portal, mode별 `key`, 조건부 재마운트는 사용하지 않는다. 기존 편집기 두 개를 같은 부모에서 유지하고 크기와 가시성만 바꾼다.

**요청·응답**은 테두리, 제목, 편집 가능/읽기 전용 표시, 보기 탭, 독립 스크롤로 구분한다. 편집 영역은 창의 남은 높이에 고정한다. 긴 Raw/JSON이 박스나 대화상자를 늘리지 않으며 요청·응답 본문 각각에서 스크롤한다. 기본 50:50이며 가운데 분할선을 드래그하거나 방향키로 조절한다. 한 패널 최소 폭은 300px을 목표로 하며 두 패널이 화면에 유지되는 범위로 제한한다. 분할선 double-click/Home은 50:50으로 복구한다. 한쪽 확대는 다른 편집기를 숨기며, 함께 보기로 원래 비율을 복원한다. 상단 설정과 전송 버튼·전송 인증은 한쪽 확대에서도 남는다. Raw/JSON 탭은 각 패널의 제목에 남겨 요청·응답 어느 쪽 보기인지 구분한다. 중복된 패널 확대 아이콘은 제거하고 상단 조작으로 통일한다.

**글자 크기**는 기본 14px, 12·14·16·18px이다. 두 패널에 함께 적용하고 문법 색 층과 textarea가 같은 크기·줄 높이·여백을 사용한다. 크기 변경 후 같은 줄의 위치를 가능한 범위에서 유지하며 초안과 선택 범위를 바꾸지 않는다. 목업 Raw는 단순 textarea이며, 실제 구현은 기존 문법 색을 유지한다.

**인증 상세**는 트래픽 신원/현재 세션을 펼쳐 비교한다. 접혀 있어도 상단 선택 인증은 계속 보인다. 대상은 Raw 또는 인증 상세에서 확인하며 기존 전송 확인·scope 검사 흐름은 유지한다. 원문/비로그인/현재 세션의 실제 전송 의미, 세션 소멸 시 잠금, explicit HUMAN 전송, exact-scope guard는 그대로 따른다. 표시 설정 변경만으로 전송하거나 인증 방식을 변경하지 않는다.

**이력**은 접힌 상태로 시작한다. 펼쳐도 편집기 전체 높이가 사라지지 않도록 이력에 독립 최대 높이·스크롤을 둔다. 기존 현재 탭 최근 결과와 저장 검증 이력·실패 시도는 의미를 합치지 않는다. 목업의 3건은 화면 배치 예시다.

## Raw와 JSON 정돈

- 각 패널이 독립적으로 Raw/JSON 정돈을 선택한다. Raw 요청은 계속 편집 가능하고 응답은 읽기 전용이다. JSON 정돈은 요청도 읽기 전용이며 “보기 전용 · 전송은 Raw 요청 사용”을 명시한다.
- HTTP 헤더와 body 경계는 원문을 변경하지 않고 찾는다. JSON 정돈은 body만 대상으로 하고, Raw에서 헤더 전체를 확인한다. JSON media type(`application/json`, `+json`) 또는 명확한 JSON 본문인 경우에만 제공한다. 단순 응답 상태만으로 JSON이라고 판단하지 않는다.
- 들여쓰기 2칸. 숫자·문자열 토큰을 그대로 보존한다. `9007199254740993`, `1.2300`, 지수 표현, escape, 중복 key, key 순서를 바꾸지 않는다. `JSON.parse`→`JSON.stringify` 방식은 숫자 정밀도·표현·중복 key가 바뀔 수 있어 사용하지 않는다.
- 구현은 JSON 토큰과 문법을 검증하면서 토큰 사이 공백만 추가하는 표시 전용 formatter로 제한한다. 새 편집기 라이브러리는 도입하지 않는다. 요청·응답·Content-Length 등 Raw는 수정하지 않는다.
- 잘못된 JSON/잘린 본문/비JSON/디코딩 불가/원문 미보존은 해당 패널에서 짧게 안내하고 Raw를 유지한다. 마스킹으로 JSON이 깨진 경우도 같은 취급이며 숨긴 값을 복원하지 않는다.
- 정돈 상한 제안: 본문 UTF-8 256KiB, 중첩 128단계, 출력 1MiB. 초과 시 “본문이 커서 Raw로 표시합니다.”로 복귀한다. 기존 요청 전송 한도 1MiB와는 다른 표시 한도이며 승인 후 실제 데이터로 조정한다. 자동 정돈은 버튼 선택 시에만 수행한다.
- Raw 편집 시 정돈 캐시를 무효화하며 패널별 최신 파생 보기 1개만 보관한다. 닫기·프로젝트 교체·Evidence 교체·unload 때 Raw와 파생 문자열·토큰을 함께 정리한다. 문자열 메모리의 즉시 물리적 삭제를 보장한다는 표현은 사용하지 않는다. localStorage·프로젝트·query cache·로그·snapshot·캡처에 원문을 새로 저장하지 않는다.
- 기존 `highlightRaw`는 HTTP 헤더/body 경계에 의존한다. 정돈된 body를 다시 HTTP처럼 처리하지 않고 JSON body용 토큰화를 재사용해야 한다. JSON 보기나 응답 한쪽 확대에서 편집 요청 textarea는 DOM에 남겨 원래 selection/scroll을 유지한다. 숨긴 편집기는 포커스·탭 이동·접근성 트리에서 제외한다.

## 검색 결과 간소화

종류 + 노드 이름을 한 줄로 표시하고 첨부한 서비스 주소·소속 API 설명 두 줄을 제거한다. 결과마다 명확한 1px 경계선, 충분한 클릭 높이, 독립 hover와 키보드 선택 표시를 유지한다. 선택 표시가 결과 전체를 합친 면처럼 보이지 않게 한다.

동일 **종류 + 표시 이름**이 여러 서비스에서 조회될 때만 `host:port`를 오른쪽에 표시한다. hostname을 임의 별칭으로 줄여 충돌시키지 않는다. scheme만 다른 서비스가 같게 보이면 그 중복에 한해 scheme까지 구분한다. 전체 경로·서비스·소속은 tooltip/접근성 설명으로 남기며, 마우스와 키보드에서 확인 가능하게 한다. 중복 판단은 화면에 나온 30개만이 아니라 전체 일치 결과를 기준으로 한 번 계산해 더 보기 후 배지가 갑자기 생기는 문제를 피한다.

색인, 전체 프로젝트 범위, 리터럴 검색, 결과 순위, 숨긴 대상 이동, 배치 유지, 기존 필터는 유지한다. 검색 지우기는 기존 사용자 표시와 배치를 지우지 않는다. 결과 소멸은 기존 일반 결과 없음 처리다.

## 객체 묶음: 겹쳐 펼치고, 밝아지면 함께 접기

**펼침**은 기존 그래프의 개별 객체 카드와 `ID → API → OBJ` 연결선을 그대로 사용한다. 별도 창·목록·격자 패널을 만들지 않는다. 주위 그래프는 검정으로 어둡게 하고, 펼친 객체와 실제 관계가 있는 신원·API·연결선은 앞에 표시한다. 묶음 가까운 Object 레인에 멤버를 세로로 펼치며, 다른 객체·묶음과 겹치는 것은 의도한 동작이다. 멤버끼리의 간격은 실제 카드 높이에 맞춰 확보한다. 기존 신원·API·다른 묶음의 좌표·크기·viewport를 바꾸거나 전체 fit을 호출하지 않는다.

열린 객체 묶음은 하나만 허용한다. 기존 청록색 묶음 띠와 `projects 9개 접기` 조작을 유지한다. 새 멤버가 모든 저장 노드의 최하단으로 밀리는 `positionInLanes` 경로에서 **펼친 객체 멤버만** 분리해 묶음 좌표를 기준으로 배치한다. API 묶음과 일반 신규 노드 배치는 유지한다. 많은 멤버는 기존 표시 제한/더 보기와 그래프 pan·zoom을 사용한다. 별도 창 내부 스크롤이나 자동 축소로 카드 읽기를 어렵게 만들지 않는다. 화면 가장자리에서는 최초 멤버가 보이는지 확인하되 다른 노드나 viewport를 자동 이동하지 않는다.

| 조작 | 제안 결과 |
|---|---|
| 묶음 double-click/Enter | 집중 보기 열기. 기존 한 번 클릭의 요약 선택은 유지. |
| 펼친 멤버 클릭·키보드 선택 | 객체 상세 표시. 집중 보기와 다른 멤버 유지. |
| 객체 상세 패널 조작·스크롤 | 집중 보기 유지. 내용 비교 중 접히지 않음. |
| 캔버스 빈 배경 클릭, 명시적 접기, Esc | 어두운 층 제거와 객체 접기를 한 번에 수행. |
| 묶음 밖 다른 노드·엣지 선택 | 먼저 접고 그래프를 밝힌 뒤 새 대상 선택. 선택 클릭을 삼키지 않음. |
| 다른 객체 묶음 열기 | 이전 묶음을 접고 새 묶음만 집중 보기. |
| 다른 메뉴/계층/프로젝트 이동 | 접은 뒤 이동. 다시 돌아와도 자동 재펼침하지 않음. |
| Request Lab 열기 | 객체 집중 보기 닫고 Lab 열기. Lab 닫은 뒤 자동 재펼침하지 않음. |
| 데이터에서 묶음·멤버 사라짐 | 최신 데이터로 멤버 갱신, 유효한 묶음이 없으면 집중 보기 닫기. |

집중과 펼침을 각각 관리하면 밝은 그래프 위에 펼친 객체만 남을 수 있다. 따라서 `openObjectGroupId` 하나를 기준으로 투영/어두움/접기를 함께 결정한다. 이 값은 현재 화면 메모리 상태이며 저장하지 않는다. 기존 프로젝트의 `expandedGroups` 중 **객체 묶음** 항목은 로딩 시 자동 집중으로 복원하지 않고, API 묶음 펼침은 유지한다. 저장 스키마를 올리거나 기존 좌표를 제거할 필요는 없다.

실제 표현은 기존 Cytoscape 노드·엣지와 `graphFocusStates`를 재사용한다. 현재 객체 선택은 같은 관측 기록의 API↔OBJ와 ID→API 문맥을 계산하므로, 집중 보기에서도 이 관계를 사용한다. 임의로 모든 신원과 API를 연결하거나 owner·Evidence를 새로 만들지 않는다. 연결선 라우팅, 카드 선택·드래그·크기 조절, 상세 패널 동기화는 기존 경로를 유지한다. 목업은 이 연결을 합성 데이터로만 보여주며 노드 드래그는 구현하지 않는다.

추가 확인이 필요한 부분은 표시 좌표와 저장 좌표의 구분이다. 현재 `readPreferences`는 보이는 모든 노드 좌표를 수집하므로, 묶음 기준으로 자동 생성한 펼침 좌표가 일반 배치 저장을 덮어쓰지 않도록 게시 경로에서 구분한다. 이전에 사용자가 저장한 멤버 좌표는 삭제하지 않는다. 사용자의 명시적 드래그·크기 조절은 기존 저장 동작을 유지하고, 자동 펼침 배치와 구분한다. 기존 저장 위치가 묶음에서 멀리 떨어져 있으면 펼침 중에는 묶음 기준 표시 위치를 적용하고, 자동 배치만으로 저장 위치를 변경하지 않는다. 확대·테마·상세 패널 변경도 저장 위치를 바꾸지 않아야 한다.

미니맵과 연결선은 열린 상태의 실제 표시 노드를 반영할 수 있다. 접으면 임시 멤버가 사라지고 일반 보기로 돌아오며 자동 fit은 수행하지 않는다. 레인 헤더/경계 계산과 드래그 제한이 겹친 멤버 때문에 다른 노드를 재배치하지 않는지 확인한다. 검정 처리는 캔버스에만 적용하고 다른 노드·엣지 클릭을 가로채지 않는다. 객체 멤버와 상세 패널 조작은 집중을 유지하며, 묶음 밖 선택과 집중 해제는 같은 전환에서 접기를 수행한다. Esc 이후 묶음으로 포커스를 복귀한다. 데이터 갱신·검색 이동·키보드 선택에서도 접기와 강조 상태가 따로 남지 않아야 한다.

## 성능과 구현 순서

1. **승인 후 Request Lab 배치부터** — `DialogContent`를 한 번 유지하고 CSS로 크기/표시를 바꾼다. 편집 영역에 flex/min-height:0를 적용해 패널만 스크롤한다. 분할선 이동은 CSS 변수/RAF로 반영하고 drop 때 React 상태를 확정한다. 입력 초안마다 resize/전체 dialog 재생성을 하지 않는다.
2. **글자·JSON 보기** — 글자·여백·스크롤의 두 층 동기화, Raw 보존, lazy formatter·상한·메모리 수명. 현재 Raw highlighter는 값과 글자 설정만 바뀔 때 재계산하고 resize/focus 전환에서 불필요한 토큰화를 줄인다. 큰 본문은 유효한 병목 측정 후 보이는 줄만 색칠하는 방식 등을 검토하며 에디터 교체를 미리 넣지 않는다.
3. **검색 표시 보완** — 기존 데이터 처리 유지, 결과 render와 중복 서비스 메타데이터·접근성만 변경한다.
4. **객체 집중 보기** — 기존 노드·관계선 유지, 묶음 기준 멤버 배치, 자동 표시 좌표와 저장 좌표 구분, 단일 열린 그룹, 원자적 접기, 검색/상세와의 연동. 같은 상태를 부모/자식 양쪽에서 독립적으로 저장하지 않는다.

각 묶음별 focused commit과 회귀 테스트를 작성한다. 위 순서는 이번 승인 범위의 구현 순서이며 새로운 후속 단계 기능을 뜻하지 않는다. 개발 중 화면/동작이 목업과 달라져야 하면 바뀐 부분만 다시 승인받는다.

## 사용자가 빌드·검증할 항목

빌드와 자동/실제 실행 검증은 사용자가 수행한다. 제품 테스트·Maven·TypeScript·Vitest·Playwright·Burp는 에이전트가 실행하지 않는다. 작성하는 회귀 검사는 다음을 대상으로 한다.

- 창/패널 확대·글자·Raw/JSON 왕복 전후 Raw 문자열, textarea 인스턴스, 초안, selection, 스크롤 보존. 닫기/unload/데이터 교체에서 파생 보기까지 정리하고 늦은 응답이 복원하지 않음.
- 숫자 정밀도·escape·중복 key·CRLF·빈 body·비JSON·잘린 JSON·깊은/큰 JSON. 보는 것만으로 요청 길이/전송 값이 변하지 않음.
- 전송 인증/세션 소멸/전송 중 잠금/원문 미보존/서버 갱신 실패의 기존 회귀.
- 검색 30개/더 보기/중복 서비스/긴 경로/결과 없음/IME/방향키·Enter/목록/그래프 이동.
- 객체 펼침 때 ID→API→OBJ 관계가 보이고 기존 신원·API·다른 묶음 좌표와 viewport가 동일. 자동 펼침 좌표는 기존 저장 위치를 덮어쓰지 않으며 명시적 드래그·크기 조절은 유지. 펼침 → 배경/다른 노드/다른 메뉴 → 복귀 때 객체는 접혀 있고 그래프는 밝음. 멤버 상세를 볼 때는 유지. 1·9·18·다수 멤버와 화면 가장자리.
- 데스크톱 라이트·다크, 1280·1920px, 작은 높이, 100%·125% 브라우저 배율. 요청·응답이 길어져도 박스 높이가 증가하지 않고 각 본문 안에서 스크롤, 버튼/패널 구분, Mac/Windows 입력, 실제 Burp는 별도 확인.
- 실제 큰 데이터의 타이핑/분할/색칠/검색/객체 표시 지연과 메모리. 목업의 빠른 반응을 제품 성능 검증으로 간주하지 않는다.

## 승인 기준과 구현 기록

독립 HTML 목업과 이 설계 문서는 승인 기준이다. 구현 상태와 직접 검증할 항목은 `IMPLEMENTATION.md`에 기록한다. 합성 Raw 편집, 창/한쪽 확대, 분할선, 글자, 테마, 이력, 검색 표시, 기존 그래프 방식의 객체 펼침을 비교할 수 있다. JSON 목업은 정해진 합성 문자열이며 실제 formatter와 대용량 데이터를 구현하지 않는다. 목업에는 실제 서버·HTTP 전송·저장 연결이 없다.

큰 JSON의 추가 표시 제한: 정돈 결과가 64KiB를 넘으면 토큰별 색칠 DOM 대신 텍스트를 사용한다. 토큰과 Raw 보존, 정돈 한도는 동일하다.
