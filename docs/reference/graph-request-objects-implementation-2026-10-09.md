# 요청 객체와 관측 그래프 구현 범위

2026-10-09 기준, FIX_obj 브랜치의 현재 변경을 정리한다.

## 요청 객체

- 경로 토큰은 숫자 또는 영문과 숫자가 섞인 값으로 제한한다. 순수 문자 경로와 v2 같은 API 버전은 유지한다.
- 원본 경로와 객체 키의 후행 슬래시는 유지하며 서로 통합하지 않는다.
- 정상 2xx 관측이 존재하는 객체만 표시하고, 동일 객체의 401·403 등 거부 관측은 함께 유지한다.
- query와 request body를 구분한다. 빈 query 값, 반복 파라미터, 필드 유무 차이를 객체 구분에 보존한다.
- 정수 객체는 원래 숫자를 표시하고, 다른 객체는 OBJ 순번으로 표시한다. 표시 이름은 객체 식별 키를 바꾸지 않는다.
- 카드의 필드명은 최대 3개를 요약하고 하단에 객체 수와 전체 필드 수를 구분한다. 개별 객체 노출은 최대 10개다.
- 기존 다중 경로 API 묶음 → 실제 경로별 API → 각 API의 객체 목록 구조를 유지한다.

## 정적 자원

- StaticResourcePolicy에서 이미지·스타일·스크립트·폰트·음원·영상 등 등록된 확장자를 우선 제외한다. 임의의 모든 확장자를 제외하지 않는다.
- 정적 자원은 판정 매트릭스와 일반 요청 객체에서 제외하지만 원본 관측은 보존한다.
- 관측 전체에서는 정적 자원 경로 묶음과 경로별 자원 묶음으로 탐색한다. 펼친 자원은 OBJ 대신 확장자를 표시한다.
- 서비스, 메서드, 원본 경로와 query를 보존하며 표시용 경로 템플릿을 판정 키로 사용하지 않는다.
- 자원 선택의 증거와 Request Lab 연결은 해당 파일의 직접 eventId를 우선 사용한다.

## 공통 그래프 동작

- 핵심 API와 관측 전체는 동일한 렌더러·배치·선택 및 ApiActions를 사용한다.
- 전체 세로 높이를 축소하기보다 가로 폭에 맞춘 읽기 배율로 시작하고 보기 전환에도 적용한다.
- 묶음은 제자리에서 아래로 펼친다. 같은 열의 아래 노드는 임시로 밀리고 접으면 원래 배치로 복원한다.
- 정적 자원 가족 요약이 경로별 묶음으로 교체될 때 기존 요약 좌표를 이어받는다.
- 관련 없는 노드·엣지는 흐리게 유지한다. 선택 API의 다른 객체를 이유 없이 함께 강조하지 않는다.
- 필터 일치 API·객체의 상단 정렬을 유지하며 Site Overview에는 상단 재배치를 적용하지 않는다.
- 등록된 Identity와 비로그인은 접근 관측이 없어도 표시한다. 관측이 없으면 연결선을 만들지 않는다.
- API 접기 버튼은 왼쪽, 객체 접기 버튼은 오른쪽에 표시한다.
- 정적 자원 API의 하이라이트·취약점 등록·삭제 UI를 복원하고 원본 API 키를 사용한다.

## 이번에 구현하지 않은 항목

- 4단계 응답 전체 객체 생성은 기본 비활성 상태를 유지한다.
- 다중 경로의 앞쪽 ID까지 달라질 때 관측 근거를 API 가족 단위로 보강하는 개선은 논의만 했으며 구현하지 않았다.
- 한글·순수 문자 slug의 자동 템플릿화와 후행 슬래시 통합은 구현하지 않았다.
- API나 객체마다 ID 수만큼 중첩 펼침 단계를 추가하지 않는다.
