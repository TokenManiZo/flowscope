# 정적 자원의 전체 관측 그래프 표시

## 판정과 표시의 경계

정적 자원 판정은 백엔드 StaticResourcePolicy와 TrafficClassifier를 따른다. 프런트엔드에 별도의 확장자 허용 목록을 만들지 않는다. STATIC_ASSET은 coverage, 판정 매트릭스, 서버 displayObjects, 미요청 경로 후보에서 계속 제외한다. 원본 관측은 보존하며, 관측 전체를 선택한 수집 그래프에서만 표시한다. 응답 본문만으로 객체를 만드는 4단계는 추가하지 않는다.

## 표시 구조

1. 기본: 접힌 경로 형식 묶음 → 접힌 정적 자원 요약.
2. 양쪽 요약 중 어느 쪽을 더블클릭하거나 Enter로 열어도 실제 디렉터리별 경로 목록과 각 경로의 접힌 자원 묶음이 나타난다.
3. 자원 묶음을 열면 그 경로의 개별 파일을 `.gif`, `.jpg`, `.css` 등 확장자로 표시한다. 개별 자원을 열면 해당 관측의 Request Lab을 연다.

마지막 파일 구간은 {file}로 표시하고 상위 디렉터리의 숫자·영문+숫자 구간은 기존 pathShape로 형식만 묶는다. 순수 문자 디렉터리와 API 버전은 그대로 둔다. 이 구조는 표시용 그룹이며, 동일 엔드포인트 또는 소유 객체라는 확정이 아니다.

서비스·메서드가 다른 관측은 별도 그룹이다. 실제 경로와 전체 쿼리가 같은 관측은 신원·출처가 달라도 하나의 표시 자원에 증거를 모은다. 쿼리 값, 인코딩, 대소문자, 후행 슬래시는 임의로 통합하지 않는다. 표시 키는 static 접두어로 기존 판정 객체 키와 분리한다.

## 관측과 제한

출처·신원 필터와 기존 수집 신뢰 조건을 적용한다. 세션 설정, 자동 인가 재전송, 검증, Request Lab·Repeater·Intruder 재전송, 응답 없는 시도, 불명확한 실행 환경, 보조 교차 출처 파일은 새 표시 대상이 아니다.

각 자원 묶음의 파일 순서는 원본 대상 키 정렬 기준이다. 같은 확장자라도 파일을 합치지 않으며, 확장자가 없으면 `확장자 없음`으로 표시한다. 쿼리·fragment는 확장자 표시에서 제외하고 원본 요청 키는 보존한다. 화면의 개별 객체 총 노출 제한은 기존 10개이며, 경로 묶음 및 펼친 경로 목록도 기존 18개 단위 노출 제한을 따른다. 검색은 접힘과 경로 목록 제한을 넘어 필요한 경로를 표시할 수 있지만, 객체 10개 제한은 유지한다.

## 증거와 상호작용

정적 자원 노드·엣지에는 판정 셀 키, 소유자, canonical resource를 넣지 않는다. 선택 상세에서는 판정 제외를 표시한다. 반복 클러스터가 다른 파일까지 포함할 수 있으므로 각 자원은 직접 관측된 eventId만 연결한다. Request Lab은 실제 eventId를 먼저 찾고 해당 기록이 없는 경우에만 기존 클러스터 대체 경로를 사용한다.

API와 자원 묶음 모두 제자리에서 아래로 펼친다. 화면 아래 공간이 부족해도 위로 뒤집거나 카메라를 옮기지 않는다. 같은 열의 아래 노드는 펼친 멤버 높이와 간격만큼 일시적으로 내려가며, 원래 접힌 좌표를 저장하므로 접으면 복원된다. 자동 배치된 멤버와 밀려난 좌표는 영구 위치로 저장하지 않는다. 가족 요약을 실제 경로별 자원 묶음으로 교체할 때에도 기존 요약 좌표를 layoutAnchorId로 전달한다. 첫 묶음은 그 좌표에 놓고 나머지는 아래로 삽입하며, 접힌 요약 좌표는 숨겨진 동안에도 유지한다. 이 메타데이터는 화면 배치에만 사용한다. 다른 경로의 자원은 집중 강조에 포함하지 않는다. 출처·신원·상태 필터의 기존 상단 정렬은 유지한다(Site Overview 제외). 전체 관측 검색, Site Overview의 신원·출처·상태 코드 강조, 작은 화면의 목록에서도 같은 표시 구조를 사용한다.

## 검증

단위 테스트는 두 단계 펼침, 서비스·메서드·쿼리·슬래시 구분, 여러 확장자와 확장자 없는 STATIC_ASSET, 반복 관측 통합, 신뢰 조건, 증거 불변성, 객체 10개 제한, 경로 노출 제한을 넘는 검색 이동을 다룬다. 화면 테스트는 양쪽 요약의 더블클릭과 정확한 파일의 Request Lab 연결을 검증한다. Playwright는 패키징된 JAR의 실제 Cytoscape에서 같은 흐름과 자원 묶음의 제자리 펼침을 검증한다.


## 초기 화면과 보기 전환

핵심 API와 관측 전체는 같은 읽기 배율·펼침 배치를 사용한다. 처음 들어오거나 두 범위를 전환하면 전체 세로 높이를 한 화면에 축소하지 않고 가로 폭을 기준으로 0.65~1 배율에서 위쪽부터 보여 준다. 긴 그래프는 이동 및 미니맵으로 탐색한다. 펼침·접힘, 선택, snapshot 갱신 때는 사용자의 카메라를 유지하며, 명시적 전체 맞춤 버튼은 기존대로 전체 그래프를 맞춘다.

## 다중 경로 판정의 현재 한계

일반 객체 projection은 마지막 숫자·영문+숫자 토큰만 `{id_n}`으로 바꾼 실제 부모 경로별로 관측 근거를 모은다. `/product/123/456/category/799/display/1`과 `/product/123/456/category/799/display/2`처럼 마지막 값만 다르면 보강하지만, 앞의 상품 ID·분류 ID까지 달라지면 각각 다른 부모 범위가 된다. 숫자·영문 외 문자가 포함된 상품명 slug는 토큰 규칙에도 맞지 않는다. 여러 숫자가 있다는 이유만으로 경로 전체를 동일 API로 확정하지 않는다. 이번 변경은 펼침 배치에 한정하며 서버 객체·매트릭스 판정 규칙을 변경하지 않는다.

## API 조작 UI 공유

핵심 API와 관측 전체는 동일한 ApiActions를 사용한다. 정적 자원 API에도 하이라이트·사용자 취약점 등록·삭제 버튼을 제공하며, 접힌 API 묶음에도 원본 API의 표시를 반영한다. 표시용 경로를 서버 관리 키로 사용하지 않고 displayOperations의 원본 API 키를 사용한다. 실제 API가 여러 개면 선택 상자에서 조작할 API를 지정하며, 기존 서버의 단일 API 등록·하이라이트 검증과 삭제 미리보기 절차를 그대로 사용한다. 같은 원본 API 키를 공유하는 여러 표시 경로에는 동일한 표시가 적용된다. 정적 자원의 사용자 표시와 판정 매트릭스 자격은 별개이며, 정적 자원 제외 정책은 유지한다.
