# UI/UX·용어 수정 설계 — 2026-10-07

## 범위와 근거

첨부 이미지 9장을 현재 프런트엔드 소스와 대조한 설계다. 이번 단계는 분석과 설계이며 제품 코드는 수정하지 않았다. 이미지 안의 표시는 수정 의도를 파악하기 위한 참고 자료로 읽었다. 기존 `ui-language-audit-2026-10-07.md`는 참고 문서이며 이번 요청의 범위를 확대하는 지시로 취급하지 않는다.

현재 밝은 배경, 얇은 경계선, 녹색 선택 상태와 HTTP 메서드 배지를 유지한다. 새로운 디자인 시스템이나 전역 CSS 개편을 도입하지 않는다. 데스크톱 작업 화면의 공간 사용, 정보 위계, 용어를 국소적으로 개선한다.

변경 순서: 그래프 → 점검 시작 → 관측 기록 → 판정 매트릭스 → 왼쪽 사이드바. 각 단계의 diff와 관련 검증을 확인한 뒤 다음 단계로 진행한다.

## 1. 그래프

### 이미지에서 확인한 문제

- 검색창이 중앙의 좁은 너비에 머물러 상단 공간을 충분히 사용하지 않는다.
- 보기·보기 범위의 설명이 필터마다 상시 노출되어 항목을 찾는 속도를 늦춘다.
- 재전송 진입점이 왼쪽 보기 전환과 오른쪽 안내에 중복된다.
- 오른쪽 상세의 API, 계정, 객체 식별자가 연속된 텍스트로 보여 정보 위계가 약하다.
- 이미지의 붉은 화살표는 객체 목록의 긴 식별자에 닿아 있다. 이를 객체 데이터 삭제로 해석하지 않고 기본 화면의 중복 식별자 노출을 줄이는 것으로 해석한다.

### 변경 설계

- 검색 영역은 도구 모음의 남는 가로폭을 채운다. 탐색·보기 전환과 확대·축소 버튼은 고유 너비를 유지한다. 좁은 화면에서는 검색이 다음 줄로 내려갈 수 있게 한다.
- `Graph filters`는 `그래프 필터`로 통일한다.
- 보기·보기 범위 제목 옆에 기존 도움말 컴포넌트를 이용한 `?` 버튼을 배치한다. 포인터, 키보드, 터치로 같은 설명에 접근하도록 한다. 판정 대상과 재전송의 차이를 설명하는 내용 자체는 보존한다.
- 상단의 재전송 중복 안내·버튼을 없애고 왼쪽 `재전송` 전환을 노드 더 보기 옆으로 이동한다. 기존 `changeGraphMode`와 전환 상태를 그대로 사용한다. 접힌 필터·좁은 화면에서도 새 위치에서 전환할 수 있어야 한다.
- 오른쪽 상세는 메서드 배지 + API 경로, 계정, 객체 요약 순으로 정리한다. 카드·구분선·간격은 기존 스타일을 재사용한다.
- 긴 객체 ID의 중복 출력을 제거하되 필요한 식별자는 한 곳에서 전체 확인·복사가 가능하게 한다. 객체 종류와 소유자 미확인 상태는 구분해서 표시한다.

### 최소 변경 지점

`RelationshipGraphView.tsx`, `GraphSearchInput.tsx`, `GraphInspectorPanel.tsx`, `GraphNodeSummary.tsx`. 공통 상세 패널은 그래프의 요구를 기존 props로 표현할 수 없는 경우에만 좁게 수정한다.

그래프 투영, 계층 이동, 검색 매칭, 노드 수 제한, 필터 의미, 소유자 저장, 판정 로직은 변경하지 않는다. 검색창이 커져도 검색 팝업의 화면 경계 계산과 전체화면 포털은 유지한다.

## 2. 점검 시작: 수집 기록·ZAP·LLM

### 원인

일반 화면의 부모가 내용 높이로 배치되고 기록 본문에 별도 높이 상한이 있다. `HumanRequestFeed.tsx`는 `max-h-96`, `LlmPass.tsx`는 `max-h-[min(24rem,24vh)]`를 사용한다. `SourcePassLayout.tsx` 역시 일반 화면에서는 높이를 전달하는 flex 구조가 아니다. 따라서 기록을 크게 보기로 전환하기 전에는 넓은 화면 아래에 빈 공간이 남는다.

### 변경 설계

- 이미지에서 제거 표시한 제목 아래 `대상 https://…` 줄은 화면에서 제거한다. 실행 대상 상태·범위 검증과 기존 대상 선택 UI는 유지한다.
- 수집 기록의 `브라우저·ZAP·LLM의 최근 요청을 함께 확인합니다` 문장은 제거한다. `계정·세션 열기`는 기록 도구 모음 가까이 배치한다.
- 제목·탭·설정 영역은 내용에 필요한 높이를 사용한다. 기록 패널은 남은 높이를 채우고 기록 본문만 스크롤한다.
- 부모 → 탭 → 활성 탭 내용 → 기록 카드에 `flex`, `flex-1`, `min-h-0`을 이어 적용한다. 화면 높이에서 임의의 픽셀을 빼는 계산이나 새로운 JS 높이 계산은 도입하지 않는다.
- 수집 기록, ZAP 요청 기록, LLM 진행 기록에 같은 높이 규칙을 적용한다. 표 머리글과 하단 기록 수·LLM 입력은 본문 스크롤 바깥에 유지한다.
- ZAP·LLM 제목 옆의 `?`로 역할 설명을 옮긴다. ZAP 설명은 `선택한 계정으로 ZAP 스캔을 실행하고 요청·응답을 기록합니다`처럼 실제 동작을 설명한다. `Human이 놓친 API`라는 추정을 기본 문구에서 제거한다.
- 기록 접기와 크게 보기, Escape 복귀는 유지한다. 설정·오류 안내가 화면보다 길어질 경우 전체 설정에 접근할 스크롤을 보장하며 기록 최소 높이를 억지로 고정하지 않는다.

### 최소 변경 지점

`InspectionPage.tsx`, `SourcePassLayout.tsx`, `HumanRequestFeed.tsx`, `LlmPass.tsx`. 공유 workspace 변경은 우선 피하고 해당 페이지에서 해결한다.

스캔 시작 조건, 대상 선택, 계정 선택, ZAP 연결, 취소, LLM 실행·추가 지시, 요청 수집·정렬·저장은 변경하지 않는다.

## 3. 관측 기록

- 검색 입력의 이름을 `번호·경로·계정 검색`으로 바꾸고 표시 번호 검색을 추가한다.
- 번호는 `eventId`가 아니라 화면에 표시한 `evidenceOrdinals`를 기준으로 찾는다. `#96`과 `96`은 기록 번호 96을 정확히 찾는 방식으로 설계한다. 일반 문자열은 기존 메서드·경로·신원 검색을 유지한다.
- 검색은 현재 탭·출처·분류 범위 안에서 작동한다. 번호 검색이라고 숨김 필터를 자동으로 바꾸지 않는다.
- 접힌 반복 기록에 속한 번호를 검색했을 때 해당 기록을 확인할 수 있도록 번호 검색 결과의 대표 행 선택을 확인한다. 전체 반복 접기 규칙을 바꾸지 않는다.
- 상세의 `분류 · 보존 정보` 블록은 이미지 요청대로 표시에서 제거한다. 저장된 분류, 원문 보존 메타데이터, 마스킹은 유지한다.
- 요청·응답 원문과 연결 판정·정책 편집의 위계를 유지한다. 원문에 실제로 저장되지 않은 본문을 복구하거나 제공하는 것으로 표현하지 않는다.

최소 변경: `EvidenceFilters.tsx`, `evidenceSelectors.ts`, `EvidencePage.tsx`.

번호 검색은 CSS·용어 수정만으로 구현할 수 없는 유일한 명시적 검색 기능 확장이다. 프런트엔드 조회 조건에 한정하며 서버 검색·저장·판정에는 영향을 주지 않는다. 계정 표시 이름까지 검색하려면 기존 계정 표시 매핑을 재사용한다.

## 4. 판정 매트릭스

- 왼쪽 BFLA/BOLA·IDOR 전환과 `주의 항목만`을 표 위의 도구 모음으로 이동한다. 필터를 바꾸는 기존 handler와 선택 상태를 유지한다.
- 전환 명칭은 `기능 권한 (BFLA)`, `객체 권한 (BOLA/IDOR)`로 풀어 쓴다.
- `판정 매트릭스 / 파라미터 커버리지 / 기존 권한 매트릭스` 탭 줄은 기본 판정 화면에서 제거한다.
- 파라미터 커버리지와 기존 권한 표의 컴포넌트·데이터 처리는 삭제하지 않는다. 현재 이 탭이 별도 화면의 진입점이므로, 구현 단계에서 같은 화면의 작은 `다른 보기` 메뉴 등 대체 진입점으로 기능 접근을 보존한다. 기본 화면을 단순화하되 기능을 잃지 않게 한다.
- 상태 문구는 서버 `status`를 읽는 프런트엔드 표시 함수에서만 변환한다. 표, 상세, 접근성 이름에서 같은 표현을 사용한다.

| 현재 | 제안 | 의미 |
| --- | --- | --- |
| 기대 차단 관측 | 정책대로 차단됨 | 차단이 기대된 조합에서 차단 결과를 관측 |
| 기대 허용 관측 | 정책대로 접근됨 | 허용이 기대된 조합에서 성공 결과를 관측 |
| 소유권 미확정 | 소유자 확인 필요 | 객체 소유 근거가 부족함 |
| 정책 미정 | 접근 정책 확인 필요 | 기대 접근 정책의 근거가 부족함 |
| BFLA 수동 테스트 추천 | 기능 권한 수동 확인 필요 | 기능 권한 조합의 수동 확인 추천 |
| BOLA/IDOR 수동 테스트 추천 | 객체 권한 수동 확인 필요 | 객체 접근 조합의 수동 확인 추천 |

`정책대로 차단됨`을 모든 코드 403에 적용하거나 `정책대로 접근됨`을 모든 코드 200에 적용하지 않는다. 기존 상태 산출 결과에만 대응시킨다. 추천·후보·사용자 취약점 확정은 계속 구분한다. 의미가 다른 다른 상태는 일괄 치환하지 않는다.

최소 변경: `MatrixPage.tsx`, `JudgmentMatrixView.tsx`, 필요한 경우 작은 프런트엔드 표시 함수 1개. Java `AuthorizationMatrixAnalyzer`와 상태 enum·서버 응답은 변경하지 않는다.

## 5. 왼쪽 사이드바

- `권한 매트릭스` → `판정 매트릭스`.
- `부가 기능` 그룹·펼침 버튼·들여쓰기를 제거하고 기존 항목을 직접 링크로 표시한다.
- 권장 순서: 점검 시작 → 계정·세션 → 점검 Gap 그래프 → 판정 매트릭스 → 관측 기록 → API·입력 차이 → 교차 신원 검증.
- `교차 신원 검증`은 이 메뉴 재분류에 포함한다. 실제 기능은 다른 계정으로 접근을 확인하는 작업이므로 `계정 간 접근 검증`을 표시명 후보로 사용한다.
- 그래프의 `점검 Gap 그래프` 이름까지 이번 이미지 요청만으로 자동 변경하지 않는다. 필요하면 별도 용어 수정 단계에서 검토한다.
- 접힌 아이콘 메뉴, 활성 강조, 모바일 메뉴, 프로젝트 관리, 테마 전환은 유지한다.
- `#matrix`, `#verification` 등 주소와 이전 주소 별칭을 변경하지 않는다. navigationGroups가 다른 화면에서도 쓰이는지 확인한 후 불필요한 그룹 상태만 제거한다.

최소 변경: `app/routes.ts`, `SidebarNav.tsx`, 기존 사이드바 동작 테스트.

## 변경 경계와 단계별 검증

- 제품 변경은 프런트엔드 JSX, 국소 클래스, 표시 문구, 메뉴 배치에 제한한다. 추가 동작은 요청된 번호 검색에 한정한다.
- API 호출 경로·요청 본문, 서버 판정·분류, 계정 인증, 소유자·역할 저장, 데이터 모델, 전송·수집 로직은 유지한다.
- 기존 작업 중인 `CodexAppServerProtocolTest.java`, 기존 용어 분석 문서와 `frontend/tmp/`는 수정하지 않는다.
- 각 단계 후 typecheck와 관련 기존 테스트를 실행한다. 번호 검색은 표시 번호와 eventId 구분, # 접두어, 반복 기록, 필터 결합을 검증한다. 메뉴·탭 배치 테스트는 새 진입 구조에 맞게 갱신한다.
- 화면 확인은 1280×800과 1920×1080을 기준으로 큰 화면 여백, 좁은 화면 줄바꿈, 긴 API·객체 ID, 빈 기록·많은 기록, 긴 설정·오류, 접기·크게 보기 복귀를 한 번에 점검한다.
- 그래프는 검색 팝업·전체화면·재전송 전환, 매트릭스는 기존 선택·상세·정책 저장 연결, 사이드바는 펼침·접힘·모바일을 확인한다.
- 스캔이나 재전송을 실제로 실행해 시각 검증하지 않는다. 기존 테스트 fixture와 읽기 전용 화면에서 확인한다.

설계 단계에서는 테스트나 브라우저 시각 검증을 실행하지 않았다. 높이 문제는 코드 근거를 확인했으며 실제 수정 후 화면에서 확인해야 한다.


## 구현 결과

5단계의 프런트엔드 변경을 완료했다. 그래프의 `18개로 접기`도 사용자 추가 요청에 따라 제거했다. 파라미터·기존 권한 표는 `다른 보기` 메뉴로 유지했고, 사이드바는 직접 링크로 정리했다. 번호 검색은 화면 표시 번호와 등록 계정 이름을 사용한다.

- 타입 검사와 프로덕션 빌드 통과.
- 프런트엔드 단위 테스트 86개 파일, 738개 테스트 통과. 마지막 공통 레이아웃 수정 후 관련 4개 파일의 74개 테스트도 통과.
- 1280×800, 1920×1080, 600×800에서 수집·ZAP·LLM 기록, 번호 검색, 매트릭스와 다른 보기, 크게 보기 및 Escape 복귀를 합성 응답으로 검증.
- 기록 표의 가로·세로 스크롤 정렬을 1024·1440·2560px에서 확인.
- 그래프 검색·배치 유지 및 중립 관측 상세 등 기존 브라우저 시나리오 검증.
- 기존 `B polling search preserves neutral evidence on A's API at 1280px` 시나리오는 quiet-group 접힘 검사에서 실패. HEAD 소스를 별도 임시 디렉터리에서 실행해 변경 전에도 동일하게 실패함을 확인했다. 이번 작업에서 그래프 판정·투영 로직을 변경하지 않았다.
- 실제 점검 대상에 스캔·재전송을 실행하지 않았다.


## 12시 첨부 화면 후속 반영

- 수집 그래프/재전송 보기 전환을 왼쪽 필터의 `보기`로 복원했다. 도움말과 기존 전환 핸들러는 유지했다.
- 객체 묶음 상세는 객체 종류, 소유자 배지, 전체 식별자를 나눠 표시한다. 긴 식별자는 패널 안에서 줄바꿈하고 복사할 수 있다. 소유자 미확정 데이터는 그대로 유지한다.
- `교차 신원 검증` 이름을 복원했다.
- 판정 표시를 `허용 대상 · 접근 관측`, `차단 대상 · 차단 관측`, `기능/객체 접근 테스트 필요`로 조정했다. 셀 툴팁과 상세에 관측·추천의 의미를 안내한다. 서버 판정, 추천, 정책, 소유자 계산은 변경하지 않았다.
- Request Lab은 분석만 수행했다. 별도 `request-lab-analysis-2026-10-07.md`에 비활성화 조건과 응답 수신 이후 기록 오류 흐름, 미확정 부분을 기록했다.
- 후속 변경 관련 단위 테스트 7개 파일 64개, 타입 검사, 프로덕션 빌드 통과. 브라우저에서 1280/1920px의 필터 위치·긴 객체 목록과 600/1280/1920px의 기록·매트릭스 회귀 시나리오 5개 통과. 외부 요청은 차단하고 합성 API 응답만 사용했다.
