# 2단계 설계: 프로젝트 전체 관계 노드 검색

상태: **목업 승인 후 2단계 구현. 빌드·테스트·실제 화면 검증은 사용자 수행 예정.**

사용자 요청에 따라 현재 버전을 **2단계 기준선**으로 삼는다. 직전 변경은 프로젝트 형식·DB 구조 버전 오류의 안내 문구와 README뿐이며, 검사 조건·저장·마이그레이션 로직은 변경하지 않았다. 추가 저장 호환성 로직은 이번 단계 범위에 포함하지 않는다.

최초 분석 기준은 `FEAT/graph-stage-01`의 `e4e090b`와 위 안내 문구 변경이었다. `FEAT/graph-stage-02`를 생성한 뒤 재개 시점의 로컬 `QA_TEMP`(`8e5a9a8`, 1단계 PR #42 및 배치 저장 수정 포함)를 병합했다. README 충돌은 최신 문서 구성과 안전 안내를 모두 유지하도록 해결했다. 기존 PR 브랜치는 변경하지 않았고, 다른 로컬 미커밋 변경은 커밋에 포함하지 않는다. 데스크톱만 대상으로 하며 빌드·테스트·실제 Burp 검증은 사용자가 수행한다.

승인 피드백: **대상 소멸 전용 화면·문구는 제외한다.** 갱신 후 사라진 대상은 검색 결과에서 제거하며, 남은 일치 항목이 없으면 기존 결과 없음 화면을 사용한다. 잘못된 대상이나 무관한 첫 결과로 자동 이동하지 않는다.

## 목업

`index.html`은 합성 예시로 만든 **상태별 화면 목업**이다. 상태·테마·너비를 전환해 검토한다. 실제 검색 엔진, 그래프 조작, 프로젝트 저장, HTTP 전송은 연결하지 않았다. 버튼으로 고르는 예시 화면을 기능 구현이나 검증 결과로 해석하지 않는다.

- 검색 결과: 종류·서비스·소속 경로, 다른 서비스의 같은 API, 접힘·표시 제한 설명.
- API 이동: 같은 그룹의 18개 제한 밖 API를 추가 표시하고 필요한 API 묶음을 연 상태.
- 객체 이동: 접힌 객체 묶음의 멤버를 개별 API 보기에서 표시한 상태.
- 결과 없음: 현재 그래프를 유지하고 검색 수정 안내.
- 라이트·다크, 1280·1920px 구성. 숫자·도메인·기록은 모두 합성 예시다.

## 검색 범위와 노드 식별

이 단계의 '전체'는 **현재 프로젝트의 전체 관계 보기에서 생성 가능한 논리 노드**다. 캔버스의 18개 표시 제한·계층·접힘을 적용하기 전의 분석 셀과 그 파생 구조가 기준이다. 모든 관측 HTTP 본문이나 프로젝트의 모든 데이터 종류를 의미하지 않는다.

| 종류 | 검색 필드 | 결과 선택 시 기본 보기 |
|---|---|---|
| Target | 기존 서비스 문자열(호스트·포트·scheme 포함) | Site Overview에서 Target 선택 |
| API 그룹 | 기존 자동 그룹 이름·서비스·그룹 키 | Site Overview에서 해당 그룹 선택. 더블클릭/Enter로 여는 기존 동작 유지 |
| API | method, 원래 path, 서비스가 포함된 operation | 현재 개별 API가 같으면 유지, 그 밖에는 해당 그룹의 API 카드 |
| 객체 | 원래 resource/객체 ID와 서비스 | 이미 보이는 관련 카드면 유지. 숨겼다면 관련 개별 API 보기의 객체 카드 |
| 신원 | 그래프가 사용하는 원래 `idn` 문자열·서비스 | 현재 관련 보기 우선, 없으면 해당 그룹에서 신원 카드 |
| 자동 API 묶음 | `operationShapeKey`의 method·경로 형식·서비스 | 해당 그룹의 요약 카드 |
| 자동 객체 묶음 | `objectGroupKey`의 기존 이름·서비스 | 해당 그룹의 요약 카드 |

REVIEW/EXCLUDE 보조 트래픽, 현재 전체 관계 보기에 포함되지 않는 미관측 경로 후보, Gap 전용 가상 조합, 등록만 된 계정, HTTP 원문·헤더·본문은 이 단계에서 추가 검색 대상으로 만들지 않는다. 검색 인덱스가 새 관계나 신원을 추론하지 않는다. 후보 검색 확대는 별도 승인이 필요하다.

검색용 semantic key는 `[종류, 서비스, 원래 값]`으로 구성한다. 이름·잘라낸 경로·18개 내 순번으로 식별하지 않는다. 렌더 ID(`operation:…`, `resource:…`, `identity:…`)와 보기별 좌표 키는 변경하지 않는다. 같은 객체/신원이 여러 API에 나타나면 서비스별 결과 하나에 관련 경로를 연결한다. 원문 resource에 서비스가 없는 경우도 `cell.op`의 서비스 문맥으로 구분하며 서로 다른 서비스를 합치지 않는다. 실제 판정·owner·Evidence 선택은 최종 projection의 기존 selection을 사용한다.

서비스·method·path 파싱은 기존 `apiGroupDescriptor`, `operationParts`, `operationShapeKey`, `objectGroupKey`와 같은 기준을 공유한다. `UNKNOWN`, 주소 없는 operation, 포트와 trailing slash 등의 기존 값은 임의로 정규화해 병합하지 않는다.

## 화면과 입력 동작

- 기존 그래프 상단 제어에 검색 입력을 추가한다. 기존 뒤로/앞으로, 그래프/목록, 확대·축소, 맞추기·전체 화면과 필터 조작은 유지한다.
- placeholder: `서비스, API, 객체 ID, 신원 검색`. 입력 하단 결과에는 종류, 원래 이름, 서비스, 소속 그룹/관련 API를 표시한다.
- 검색어가 없을 때 전체 결과를 자동으로 열지 않는다. 임의의 검색 이력이나 최근 항목은 만들지 않는다.
- 검색은 대소문자를 무시하는 리터럴 부분 일치다. 공백으로 나눈 토큰은 모두 일치해야 하며 최소 한 글자부터 검색한다. 정규식·유사 검색·초성·고급 문법은 추가하지 않는다. 문자열 검색을 위해 `%2F` 등을 자동 decode하지 않는다.
- 정렬은 주 이름 완전 일치 → 주 이름 prefix → 주 이름 부분 일치 → 서비스/소속 문맥 일치 순이다. 동률에는 현재 서비스/보기, 종류, 원래 값의 고정 순서를 쓴다. 위험 점수를 검색 순위로 해석하지 않는다.
- 처음에는 30개 결과만 DOM에 표시하고 '결과 30개 더 보기'로 늘린다. 검색 매치 수와 화면에 렌더한 수를 구분한다. 무한 스크롤·가상 목록은 초기 구현에서 추가하지 않는다.
- 같은 API가 두 서비스에 있으면 서비스명을 항상 보여 준다. 긴 문자열은 줄임표·전체 값 tooltip으로 제공하고 HTML로 해석하지 않는다.
- 입력 중에는 현재 보이는 직접 일치 노드만 임시 외곽 점선으로 표시한다. 계층 이동, 자동 fit, 묶음 펼침, 배치 저장은 하지 않는다. 접힌 묶음 안의 일치가 있다면 작은 '멤버 일치' 표시를 사용한다.
- 검색 결과 키보드 ↑/↓ 이동·Enter 선택, Esc 팝업 닫기, Tab으로 정상 이동을 지원한다. 조합 입력(composition) 중 Enter/방향키를 검색 선택으로 처리하지 않는다. 문서 전역 Cmd/Ctrl+F는 가로채지 않는다.
- 검색 지우기는 결과 목록·검색 강조만 해제한다. 현재 계층·선택·사용자 배치·기존 강조 필터는 유지한다.
- 결과 팝업은 캔버스나 panel의 `overflow:hidden`에 잘리지 않게 표시하며 화면 안쪽으로 너비/위치를 제한한다. 그래프 fullscreen일 때는 해당 fullscreen 영역에 portal을 둔다.
- 검색 후 선택된 노드가 기존 강조 필터에 해당하지 않더라도 선택 카드 자체와 검색 외곽선은 식별 가능하게 유지한다. 출처·HTTP 상태·확정 위험 표시는 기존 색과 의미를 유지한다.

## 결과 선택과 배치 보존

1. 클릭한 stable key를 **최신 snapshot**에서 다시 찾는다. 프로젝트 교체나 데이터셋 변경이면 취소한다.
2. 같은 서비스의 현재 보기에서 대상이 이미 표시되면 그 보기를 유지한다. 다른 보기면 종류별 기본 보기를 고른다. 객체가 여러 API에 연결됐으면 현재 API → 현재 그룹의 관련 API → 고정된 원문 정렬의 첫 API 순으로 고르고, 결과/상세에 실제 선택한 API 경로를 표시한다.
3. API는 기본 18개와 선택 대상 한 개의 합집합으로 투영한다. 필요한 API 형식 묶음을 열되 다른 그룹/레인을 일괄 정렬하지 않는다. 객체는 개별 API 보기에서 기본 18개 객체와 대상 한 개를 합친다. 신원이 제한 때문에 없으면 그 신원과 연결된 API 한 개를 추가 포함한다.
4. 자동 묶음 결과 자체는 요약 카드를 선택한다. 모든 멤버를 자동 펼치지 않는다. 자동 객체 묶음으로의 이동은 그 묶음과 관계 있는 API 한 개를 먼저 표시해 묶음 요약이 반드시 만들어지게 한다. API 묶음은 현재 생성 규칙상 멤버 두 개가 필요하므로, 기본 제한 안에 대표가 없으면 최대 두 API만 추가 표시한다.
5. `searchAnchor`는 마지막 선택 대상/관련 API만 보관하는 메모리 상태다. 검색 문자열을 지워도 유지한다. 다음 검색 결과 선택, 다른 보기 이동, '추가 표시 해제', 기존 '18개로 접기'/초기화, 프로젝트 교체 시 해제한다. 여러 검색 결과의 추가 노드를 누적하지 않는다. 화면에 '검색으로 1개 추가 표시 · 해제'를 보여 준다.
6. navigation 변경과 필요한 펼침 상태는 같은 workspace update에서 적용한다. 대상 보기의 저장된 geometry를 먼저 복원하고, 위치 없는 노드만 1단계 신규 노드 배치 규칙을 따른다. 필요한 자동 API 묶음 펼침과 마지막 계층은 기존 프로젝트 저장 규칙을 따른다. `searchAnchor`, 검색어·결과·선택은 저장하지 않는다.
7. 새 projection에서 대상의 존재와 실제 렌더 완료를 확인한 뒤 현재 selection으로 상세 패널을 연다. 패널 너비/레인 헤더를 반영한 유효 캔버스 영역을 기준으로 대상을 노출한다. 목록 모드에서는 해당 행으로 이동한다. 객체/신원 등 그룹 API 표에서 직접 표현하지 않는 대상은 개별 API 목록으로 이동한다. Target 결과는 Site Overview의 그래프로 보여 주고 renderer가 없으면 선택 가능한 Target 요약을 제공한다.
8. 현재 줌은 유지하고 대상이 이미 유효 화면 안에 있으면 팬하지 않는다. 화면 밖이면 최소한의 팬으로 노출한다. 카드가 유효 영역보다 클 때만 줌을 줄이되 기존 최소 줌 40%를 유지한다. 최소 줌에서도 큰 카드가 넘치면 유효 영역 중앙에 두고 사용자가 팬으로 나머지를 본다. 전체 그래프 fit이나 정렬은 실행하지 않는다. 이동 후 viewport는 기존 저장 규칙을 따른다.

이 방식은 표시 제한을 18→36→…로 크게 늘리는 방식보다 렌더링 비용이 작고, 기존 좌표 키와 정렬 기준을 유지한다. 개별 객체를 찾을 때 다른 계층으로 이동하는 것이 주된 UX tradeoff다. 목업 승인 시 이 이동 방식을 함께 확정한다.

노드 선택에 필요한 비동기 대기는 `datasetRevision + requestId + stable key`로 관리한다. 새 결과 선택·사용자 계층 이동·드래그·프로젝트 교체가 발생하면 이전 대기를 취소한다. 고정 `setTimeout`으로 기다리지 않는다. projection에서 대상이 없거나 렌더러 오류면 완료되지 않는 pending 상태를 남기지 않고 안내/목록 경로를 제공한다. 상세 패널을 열어 캔버스 폭이 바뀐 뒤 한 번만 노출 계산하고 ResizeObserver 저장 루프를 만들지 않는다.

## 성능 설계

검색 인덱스는 분석 cells에서 중복 제거한 가벼운 항목과 문맥 참조로 만든다. 각 항목에 전체 cells/Evidence 배열을 복제하거나 각 계층의 `projectHierarchy`를 호출하지 않는다. API 묶음 기준은 제한 전 전체 operation으로 계산하되, 선택 대상에 맞는 표시 카드가 생성되도록 reveal을 연결한다.

- 입력값은 즉시 반영하고 검색 계산은 120ms debounce한다. 최신 입력·인덱스 generation만 결과를 적용한다.
- snapshot의 검색 관련 cells/필드가 바뀔 때만 인덱스를 갱신한다. 서버가 snapshot 배열을 매번 새로 주는지부터 확인한다. viewport·테마·panel·선택·출처 강조 변경은 재색인하지 않는다.
- 초기안은 변경된 snapshot에서 한 번 순회하고 중복 제거한 인덱스로 교체한다. 신원·owner 변경만으로 불필요하게 전체 항목을 복제하지 않는다. 문자열을 매 키 입력에서 다시 소문자로 만들지 않고 정규화한 검색 필드를 재사용한다.
- 검색은 O(N) 인덱스 순회이고 단순 debounce만으로 대형 데이터 지연이 사라진다고 주장하지 않는다. top 30을 bounded ranking으로 뽑으며 전체 결과 정렬을 매번 하지 않는다. 결과 추가 표시 시 필요한 범위만 늘린다.
- 인덱스/검색 처리에서 50ms 이상의 main-thread 작업이 확인되면 취소 가능한 chunk 처리를 먼저 적용한다. 이 지표는 평가 기준이며 현재 측정 결과가 아니다. Web Worker·trigram 인덱스·서버 검색 API는 근거가 생기면 검토한다.
- 입력 중 graph projection identity는 유지하고 Cytoscape data/class만 batch 갱신한다. 같은 매치 집합이면 반복 적용하지 않는다. HTTP 원문 조회·분석 실행·프로젝트 저장 요청은 유발하지 않는다.
- snapshot 갱신 빈도와 비용을 함께 측정한다. 검색 창 열림 여부만으로 무거운 인덱스 재생성을 숨기지 않는다. 프로젝트 교체 시 인덱스·검색어·타깃·대기를 비우고 이전 프로젝트 참조를 남기지 않는다.

새 검색 API나 프로젝트 schema 변경은 초기 구현에 필요하지 않다. 저장 상한은 1단계와 동일하다. 검색으로 처음 방문하는 보기도 보관 수·좌표 수 한도에 영향을 줄 수 있으므로, 저장 오류를 숨기거나 기존 좌표를 자동 삭제하지 않는다.

## 예외와 상호작용

| 상태 | 동작 |
|---|---|
| 프로젝트에 논리 노드가 없음 | 검색어를 입력하면 일반 결과 없음 화면 사용. 기존 수집/분석 흐름 유지. |
| 결과 없음 | 검색어 수정 안내, 그래프·선택·viewport 유지. |
| 같은 이름/ID, 다른 서비스 | 서비스별 별도 결과. 객체·신원 문맥도 서비스와 관련 API로 확인. |
| 결과 표시 후 대상 소멸 | 최신 상태에서 결과를 제거하고 선택 대기를 취소. 남은 일치 항목이 없으면 일반 결과 없음 화면 사용. 별도 소멸 문구나 무관한 결과로 자동 이동하지 않음. |
| snapshot 조회 실패 | 마지막 데이터임을 표시하고 결과 이동을 비활성화. 기존 snapshot 재시도 사용. |
| 데이터 교체/프로젝트 전환 | 입력·인덱스·검색 anchor·pending 모두 제거. 같은 문자열이라도 이전 결과 재사용 금지. |
| 검색 대상은 있으나 선택한 문맥 API 소멸 | 다음 결과 선택 시 남아 있는 같은 서비스의 관계 문맥을 다시 고름. 문맥이 없으면 검색 결과에서 제외. |
| 저장된 배치 조회/저장 실패 | 기존 오류 표시 유지. viewport 이동을 저장 성공으로 표시하지 않음. |
| 위치 잠금 | 검색·선택·viewport 이동 허용. 기존 노드 좌표 이동 금지. 신규 노드 배치는 1단계 규칙 적용. |
| '18개로 접기'/추가 표시 해제 | anchor를 제거. 사라진 대상이면 선택도 정리. 저장 geometry는 유지. |
| renderer 불가/목록 모드 | 검색어 유지, 대상 종류에 맞는 목록/요약으로 이동. Canvas 선택과 다른 셀 행 ID를 혼동하지 않음. |
| 라이트·다크/확정 위험·출처 강조 | 검색은 별도 외곽 점선, 선택은 기존 표현. 위험 테두리·카드 출처·코드색을 덮지 않음. |

검색 인덱스는 기존 마스킹된 분석 식별자만 사용한다. raw Authorization·Cookie·본문·live Request Lab 초안을 읽거나 캐시·로그에 추가하지 않는다. 결과 하이라이트를 위해 `innerHTML`을 사용하지 않는다.

## 구현 구성

1. **논리 노드 목록과 검색 함수** — `graphSearch.ts`에서 범위·중복 제거·서비스 문맥·리터럴 매치·정렬·top N을 구현. 제한/접힘/다른 서비스가 포함된 순수 회귀 테스트 작성.
2. **검색 입력과 현재 화면 강조** — `GraphSearch.tsx`, `RelationshipGraphView`, `CytoscapeGraph`에 input/listbox와 독립 검색 상태 추가. 입력만으로 계층/좌표/저장 요청이 바뀌지 않는 테스트 작성.
3. **결과 이동과 제한 예외** — `graphHierarchy`에 소수 reveal 대상 옵션, `RelationshipGraphView`에 취소 가능한 pending 이동 추가. 기존 요약 패널의 동일 reveal 경로를 함께 사용. 기존 IDs·geometry 복원·Evidence 선택을 유지.
4. **수명/오류/데스크톱 목록·접근성** — 데이터 교체·snapshot 소멸·IME·Esc·fullscreen portal·위치 잠금·viewport 노출·렌더러 fallback 처리. 필요한 README와 단계 기록을 함께 묶고 코드 변경 후 `graphify update .` 실행.

범용 검색 프레임워크나 후속 단계 색 표시/다중 선택 상태는 추가하지 않았다. 설계 변경이 필요하면 변경 부분만 목업을 다시 보여 주고 승인받는다. 검색 인덱스는 Evidence·판정·owner만 달라진 snapshot에서 재사용하고, 검색 순위는 필요한 결과 수까지만 정렬한다. 큰 실제 데이터의 지연 시간과 메모리는 아직 측정하지 않았다.

## 사용자가 수행할 완료 확인

회귀 테스트는 구현과 함께 작성하되 실행·빌드·실물 검증은 사용자가 수행한다. 아래는 **예정된 검사**이며 통과 보고가 아니다.

- 다른 계층, 19번째 이후 API/객체, 접힌 API/객체 묶음 멤버, 같은 path/ID를 가진 다른 서비스 검색·이동.
- 신원/객체의 복수 API 문맥, 자동 묶음 1개만 남는 경우, UNKNOWN/주소 없는 operation 처리.
- 입력·결과 선택·검색 지우기·18개 접기 전후 저장 모델 좌표/크기 동일성. 신규 대상만 배치되는지 확인.
- 기존 출처/신원/코드 강조, 위험 상태·Evidence 연결, 위치 잠금, 요약 패널 API 이동 회귀 확인.
- snapshot 변경/오류, 빠른 연속 선택, 계층 이동/드래그 중 취소, 프로젝트 A/B 교체, 저장 오류 상태 확인.
- Mac/Windows 키보드, 한국어 IME, 라이트·다크 1280/1920px, desktop 목록·fullscreen·상세 패널 resize 확인.
- 기존 프로젝트 JSON/SQLite 재열기에서 schema 변경 없이 1단계 배치가 유지되는지 확인.
- 작은/중간/큰 실제 데이터에서 색인 시간·검색 지연·long task·메모리·Cytoscape rebuild 횟수·배치 API 요청 수 측정. 비교를 위해 합성 1천/1만/5만 논리 항목도 사용할 수 있으며 이는 지원 용량 약속이 아니다.
- 저장/데이터 경로가 포함되므로 저장소 루트의 `mvn clean verify`, 실제 Burp 확인을 구분해 기록.

추가한 Playwright 파일은 `frontend/e2e/graph-search.spec.ts`다. 합성 API 응답을 사용해 라이트·다크 1280·1920px에서 실제 노드 드래그 전후 모델 좌표, 입력 중 저장 요청, 제한 밖 API 선택, 검색 지우기 후 선택 유지를 확인한다. 해당 테스트와 브라우저 캡처도 아직 실행하지 않았다.

## 승인된 동작

**상단 검색 + 종류/서비스/경로 결과 목록**, **숨긴 객체는 개별 API 보기에서 노출**, **기본 표시 제한을 유지하며 대상만 임시 추가**, **검색 지우기로는 선택/계층/배치를 되돌리지 않음**, **대상 소멸은 결과 없음으로 처리**를 승인받았다. 검색 함수·UI·이동·viewport·수명 관리 회귀 테스트를 추가했지만 실행하지 않았다. 소스 diff 검토와 `git diff --check`만으로 런타임 동작을 검증했다고 주장하지 않는다.
