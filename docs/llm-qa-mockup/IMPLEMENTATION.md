- 작업 브랜치: `FIX/LLM_RECORD_VIEW`
- 기준: 사용자 지정 포크 `TokenManiZo/flowscope`, `FEAT/graph-stage-01 774194b`. QA_TEMP에 직접 수정하지 않았다. 기본 checkout의 별도 작업은 보존했다.
- 승인 범위: A 모델 배치, API·입력 필드 각각의 도움말, 같은 페이지에서 기록 확대와 높이 조절. HUMAN·ZAP 요청 표에도 같은 읽기 기능을 추가했다.

## 구현과 선택 이유

모델 선택은 LLM 제목 오른쪽에서 찾고, 완료 후 다음 탐색 모델과 지난 실행 요청 모델은 구별한다. 소개 문구는 API 요청과 응답을 기록한다는 표현으로 바꿨다. 근거 등록 수는 API와 입력 필드의 설명 아이콘을 각각 제공하며 기존 서버 값과 중복 제거 의미는 유지한다.

SourcePassLayout과 작은 RecordView 컨트롤에서 기록 확대와 높이 조절을 공유한다. 확대는 설정·단계 표시를 숨기고 본문을 기록에 사용한다. 설정은 계속 마운트되어 수집이 중단되거나 선택이 초기화되지 않는다. 별도 모달·새 창·브라우저 전체화면 API 대신 같은 페이지를 사용했다. 전역 작업 공간이나 그래프 코드는 수정하지 않았다.

원래 크기와 Escape는 이전 본문 스크롤을 복원한다. 목록 DOM, HUMAN·ZAP 검색어, LLM 추가 지시 초안은 유지한다. 원문 창의 Escape는 먼저 그 창만 닫는다. 프로젝트 교체·화면 이탈은 확대 상태를 해제한다. 기본 높이 조절은 드래그·방향키를 지원하고 160~600px 범위로 제한한다. 실행 중 추가 지시의 전송 성공은 기존 서버 의미 그대로다.

## 한계와 병합

이 브라우저 확인은 실제 제품 프론트와 합성 데이터의 조합이다. 실제 Burp·ZAP·Codex 실행 및 기존 Playwright 전체 suite는 수행하지 않았다. Java skip 4개를 실물 검증으로 주장하지 않는다. HUMAN·ZAP은 기존 최근 저장 HTTP 관측 200건만 표시하며 확대가 전체 기록 추가 조회를 뜻하지 않는다. 모바일은 범위 밖이다.

기준 Head는 작업 중 재조회한 시점에도 774194b였다. 이 변경은 점검 프론트·회귀 테스트·사용 문서에 한정하며 DB/API/실행기 코드는 바꾸지 않는다. 이후 다른 작업이 같은 줄을 수정하면 충돌은 다시 확인해야 한다. 푸시와 QA_TEMP 병합은 수행하지 않았다.

구현 커밋과 다른 로컬 작업 `FEAT/graph-stage-02 bd99544`를 `git merge-tree --write-tree bd99544 HEAD`로 가상 병합한 결과 exit 0, 충돌 없음이었다. 실제 병합이나 checkout은 하지 않았다. 해당 작업의 미커밋 변경은 이 검사에 포함하지 않았다.
