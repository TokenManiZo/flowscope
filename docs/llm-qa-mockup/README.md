# LLM QA 검토 목업

최초 목업은 `FEAT/LLM_QA_MOCKUP`, `origin/QA_TEMP 8357e20` 기준이었다. 승인된 A 배치와 개별 설명 아이콘을 `FIX/LLM_RECORD_VIEW`에 반영했으며, 구현 기준은 사용자가 지정한 포크 `FEAT/graph-stage-01 774194b`다. `screen=human` 또는 `screen=zap`으로 같은 기록 보기 기능의 전후를 볼 수 있다. 화면은 LlmPass·SourcePassLayout의 배치와 사용자가 제공한 QA 캡처를 예시 데이터로 재구성했으며 실제 제품 캡처가 아니다. 1280×720과 1920×1080 데스크톱 전용이다.

## 검토 순서

1. 모델 위치: 현재 배치와 A(제목 오른쪽), B(설명 아래 왼쪽), C(기존 위치 강조)를 같은 데이터로 비교한다. A를 우선 추천한다. 위에서 설정을 찾고 기존 높이를 유지할 수 있다. B는 왼쪽에서 순서대로 읽기 쉽지만 한 줄 더 필요하다. C는 변경 범위가 작지만 기존 시선 이동이 남는다. 실제 실행 중에는 모델을 바꿀 수 없으며, 완료 화면의 다음 실행 선택과 지난 실행 모델 표시는 구분한다.
2. 기록 읽기: 각 개선안의 “크게 보기”는 같은 페이지 본문을 진행 기록에 사용한다. 사이드바와 작업 메시지·계정·이번 실행 모델·HTTP 수·추가 지시는 유지한다. 원래 크기 또는 Escape로 이전 화면 위치와 기록 스크롤을 복원한다. 새 창, 모달, 브라우저 전체화면 API는 사용하지 않는다. 기본 보기의 얇은 조절 손잡이는 드래그 또는 위아래 방향키로 기록 높이를 조절한다. 접기/펼치기는 독립 동작이다.
3. 용어: 소개는 “LLM이 서비스를 둘러보며 API 요청과 응답을 기록합니다.”로 제안한다. “선언”은 “근거로 등록한”으로 풀어 쓴다. 도움말은 API와 입력 필드 각각 또는 한 번에 설명하는 두 형태를 비교한다. 실제 응답 관측 수와 근거 등록 수의 차이·중복 제거를 설명한다. 집계 의미·서버 값은 변경하지 않는다. 여섯 수치의 3열×2행은 유지한다.

API 설명: “LLM이 화면 코드나 API 문서에서 찾아, 근거와 함께 등록한 API 수입니다.” 입력 설명: “등록한 API에 보낼 수 있는 입력 항목 수입니다. 예: 검색어, 페이지 번호, ID.” 합친 설명: “LLM이 화면 코드나 API 문서에서 찾아, 근거를 연결해 등록한 API와 입력 필드 수입니다.” API는 실제 요청 관측과 별도 기준이며 의미가 같은 항목은 중복 집계하지 않는다. 입력은 같은 API의 같은 필드를 한 번 센다.

실행 전·실행 중·완료·시작 실패는 정적인 예시 상태다. 로그인·시작·중단·삭제·모델 목록 조회·추가 지시는 모두 표시만 하며 실제 네트워크 호출이 없다. 모델 옵션도 예시이며 현재 계정의 실제 제공 모델 목록이 아니다. 인증정보는 포함하지 않는다. 그래프와 모바일은 범위에서 제외한다.

목업 자체는 실제 수집을 실행하지 않는다. 아래 최초 목업 결과는 이전 검토 결과다. 이번 제품 구현·검증 결과는 [IMPLEMENTATION.md](IMPLEMENTATION.md)에 별도로 기록했다.
