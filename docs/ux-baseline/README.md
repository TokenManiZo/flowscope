# 승인된 UI/UX 목업과 구현 검토

기준은 최신 origin/QA_TEMP `2ed0b7f`, 단일 작업 브랜치는 `codex/ux-accounts-evidence`입니다. 사용자 변경이 있는 기존 QA_TEMP 체크아웃은 보존합니다.

사용자의 최신 지시에 따라 한 브랜치에서 작업별 커밋으로 진행합니다. 수집·로그인·탐색·인가 동작을 보존하는 화면 배치·표시·기존 데이터 연결은 승인되었습니다. 기능 변경이 필요한 항목은 별도 확인 전 보류합니다. QA_TEMP 병합은 별도 승인 대상입니다.

## 단계와 검증

1. 기준 확인 → 최신 HEAD와 동일 예시 데이터로 개선 전·후 웹 화면 고정
2. 계정·수집 → H/S/L 저장 응답 관측 건수, 시작/종료 안내, 기록 번호
3. LLM → 기존 메시지 피드와 계정 표, 접기·종료 표시·하단 버튼·아이콘 정렬
4. API·입력 차이 → 같은 API의 요약과 입력 근거 비교, Method/API 열·HSL 글자색·HTTP 코드
5. 관측 기록·상세 → 개별 요청의 열 분리, 마스킹 원문 우선, 클릭형 역할·접힌 정책
6. 통합 검증 → 관련 회귀, 두 테마·데스크톱, `mvn clean verify`, Playwright와 한계 기록

그래프는 보류하며 모바일은 설계·구현·검증하지 않습니다. 작업별 구현·회귀·필요 README 변경을 집중된 커밋으로 묶습니다.

## 웹 비교

`http://127.0.0.1:18843/`에서 화면·해상도·상태를 고릅니다. 라이트·다크 전후 비교와 조작 가능한 개선 목업을 제공합니다. `/baseline/`은 최신 QA_TEMP의 고정 빌드, `/actual/`은 작업 브랜치의 제품 빌드입니다.

- 데스크톱 1280×720, 1920×1080
- 계정·세션, 직접 수집, LLM 탐색, API·입력 차이, 관측 기록
- 기본·빈 상태·실행 중·조회 실패·연결 해제·추가 지시 실패
- 목업의 시작·전송·저장은 예시 시뮬레이션; 서버는 GET/HEAD만 허용

`snapshot.json`은 가상 데모 3계정·21관측·8API입니다. 전후는 같은 스냅샷과 실행 상태 fixture를 사용합니다. 요청·응답은 양쪽 모두 합성된 마스킹 예시이며 실제 Burp·ZAP·Codex 수집 결과가 아닙니다. 실제 인증정보나 프로젝트 데이터를 예시 파일에 넣지 않습니다.

계정 건수는 저장된 HTTP 응답 관측을 각각 한 번 셉니다. repeatCount는 합산하지 않습니다. laneAccountId 우선, 없는 과거 데이터는 등록된 idn을 사용합니다. 연결 상태와 누적 건수는 독립적입니다.

## 변경 전 검증

최신 QA_TEMP에서 `mvn clean verify` 통과: 프론트 609개, Java 792개 중 실패·오류 0개와 제외 3개. 이는 변경 전 기준 검증입니다. 실제 연동 검증은 수행하지 않았습니다.

목업 검사: 라이트·다크 × 두 해상도, 개선 전 20장·개선 후 20장, 추가 LLM 상태 캡처와 동작 검사 11개 통과. `verification.json`에 결과를 기록합니다.

## 다시 실행

최종 제품 검증은 [IMPLEMENTATION_VERIFICATION.md](IMPLEMENTATION_VERIFICATION.md)에 기록했습니다. 비교 페이지의 “구현 화면 열기”에서 제품 빌드를 확인할 수 있습니다. 제품 캡처는 `actual-captures/`, 검증 결과는 `actual-verification.json`입니다.

루트에서 설치된 Maven으로 제품을 빌드합니다. 생성 경로는 `target/generated-resources/react-web`입니다. Node로 `docs/ux-baseline/server.mjs`를 실행하면 로컬 18843에서 검토할 수 있습니다. `BASELINE_APP`은 별도로 보존한 QA_TEMP 빌드 경로입니다. `capture.mjs`는 설치된 Chrome과 Playwright로 목업 캡처를 생성합니다.

## 확정할 화면 방향 (사용자 피드백 반영)

- 기존 점검 시작을 공통 기본 틀로 삼습니다. 간결한 수집 컨트롤, 계정별 표, 하단 요청·진행 기록의 배치와 스타일을 유지합니다.
- LLM은 기존 하단 진행 기록에서 작업명·탐색 경로·현재 상태·메시지·HTTP 기록을 함께 표시합니다. 메시지의 원 제목·내용·상태를 보존하며 계정 선택 표와 진행 기록을 각각 접고 펼칩니다. 계정 표는 기본으로 접혀 있고 설정할 때 펼칠 수 있습니다. 진행 기록은 기본으로 펼쳐 최신 메시지가 보이며, 추가 지시 입력은 1280×720에서도 처음 화면에 보이게 합니다. 시간·횟수는 작은 보조 줄에 둡니다.
- LLM 계정 표는 비로그인과 등록 계정의 체크박스, 로그인 상태, 브라우저 로그인·다시 로그인 버튼 구성을 유지합니다. 이번 목업에서 실제 브라우저 로그인은 수행하지 않습니다.
- API 목록은 HUMAN 요청 시트처럼 Method와 API를 별도 열로 둡니다. H/S/L은 한 출처 칸의 글자에 색을 주고, 응답 여부 문장 대신 HTTP 상태 코드를 표시합니다.
- 관측 상세의 필수 역할은 미지정·Anony·User·LV1·LV2·Admin 등 클릭형 선택입니다. Anony는 Anonymous 표시 이름입니다. 관측된 계정 역할은 읽기 전용으로 구별하며 정책 선택으로 변경하지 않습니다.
- Method 배지는 60×22로 맞추고 가운데 정렬합니다. HTTP 2xx/3xx/4xx/5xx는 녹색/파란색/황색/빨간색으로 구별합니다. 색상은 HTTP 응답 구분이며 인가 판정으로 사용하지 않습니다.
- 기록 번호와 내부 Evidence ID 연결을 유지합니다. 그래프는 보류합니다.


LLM 실행 버튼은 맨 아래 왼쪽입니다. 실행 세부정보 위치는 유지합니다. 로그인 버튼은 110×24, 아이콘 칸은 12px로 정렬합니다.
