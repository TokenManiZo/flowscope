# 승인된 LLM UI와 모델 선택 통합

- 작업 브랜치: `FIX/LLM_UI_MODEL_INTEGRATION`, 별도 worktree.
- 기준: QA_TEMP `8bc618f`와 승인된 UI/UX `d2037ef`.
- 목업: 별도 `FEAT/LLM_MODEL_MOCKUP` 브랜치에서 전후·라이트·다크 비교를 제시한 뒤 사용자가 진행을 승인했다.

`LlmPass.tsx`의 설정 영역, 시작 버튼, 전체 레이아웃 세 충돌을 결합했다. QA_TEMP의 모델 목록 조회, 실행별 모델 전달, READY인 등록 계정 복원, 사용 불가 모델 차단, 목록 조회 실패 시 기본 모델 실행을 유지한다. 서버·공급자의 모델 계약은 변경하지 않는다.

모델 선택은 계정 접기 위의 한 줄에 배치하고, 실행 중에는 요청 모델을 읽기 전용으로 표시한다. 시작·초기화 버튼은 기존 하단 왼쪽 배치를 유지한다. 계정과 실행 세부정보 접기, 3열 × 2행 실행 수치, 메시지·트래픽 피드를 유지한다. 다음 실행의 편집 가능 여부와 지난 실행 결과의 표시 여부를 분리하여 완료 후에도 결과가 사라지지 않는다. 지난 요청 모델은 실행 세부정보에 남아 다음 선택과 구별된다. 한쪽 파일 전체를 선택하는 방식은 모델 기능 또는 승인된 화면을 되돌리므로 사용하지 않았다.

모델 테스트의 계정 선택은 표를 펼친 뒤 검증하도록 조정했고, 기존 완료 수치 테스트의 모델 목록 응답을 명시했다. 완료 결과를 유지한 채 다른 모델로 시작하는 회귀 테스트를 추가했다. 예시 서버에도 모델 필드와 명시적인 예시 목록을 제공한다. 실제 계정 모델 목록이나 실행을 사용하는 서버가 아니다.

검증: 관련 LlmPass 테스트 13개 통과, TypeScript 검사 통과. 전체 `mvn clean verify`는 실행했으나 사용자가 전체 빌드·화면 확인을 직접 하겠다고 요청하여 진행 중 중단했다. 전체 빌드 성공 또는 실제 웹 검증 완료로 보고하지 않는다. 실제 Burp·ZAP·Codex 실행은 수행하지 않았다. `graphify update .`의 AST 관계 그래프 갱신은 완료했다.

QA_TEMP 반영 및 원격 push는 수행하지 않았다.
