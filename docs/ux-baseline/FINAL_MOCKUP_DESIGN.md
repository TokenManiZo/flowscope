# API·입력 차이 / 관측 오른쪽 패널 목업

2026-10-03 · FIX/UI_UX · 제품 기준 커밋 595b86b

첫 목업 설계 단계에서는 제품 소스, 데이터 저장, 서버 API, 인가 판정을 변경하지 않았다. 이후 사용자 진행 승인에 따른 구현·검증은 FINAL_IMPLEMENTATION.md에 기록한다. QA_TEMP 병합은 별도 승인 대상이다.

## 비교 방법

`final-review.html`에서 개선 전·후의 라이트·다크 화면을 동시에 비교한다. 1280×720 / 1920×1080을 선택할 수 있다. 개선 전은 현재 배치의 재현이며 실제 운영 화면 캡처가 아니다. 전후에 같은 합성 계정·경로·관측·선언 데이터를 사용한다. 모든 인증정보는 마스킹된 예시다. 모바일 목업은 없다.

## 1. API·입력 차이

- 문제: 긴 설명과 두 정보 박스가 표를 아래로 밀고, 관측이 없는 선언 후보가 빨간 오류처럼 보인다.
- 설계: 제목 바로 아래에 API 비교 표를 배치한다. 설명 문장, 부분 파싱 안내 박스, LLM 실행 요약 박스, 선언 후보의 빨간 안내 배지를 제거한다.
- 이유: 관측·선언·입력 수, H/S/L, HTTP 상태로 목록을 먼저 읽게 한다. 관측 없음은 HTTP `—` / 관측 `0` / 선언 수로 나타낸다.
- 유지: Method 색상, H/S/L, 실제 API·산출물 후보 구분, 필터·집계·상세 동작. 필터와 집계는 표 헤더 안에 둔다. 집계는 떠 있는 메뉴로 열어 표 크기를 바꾸지 않는다. 부분·실패 파싱 건수는 집계 안에 남는다.
- 조회 실패는 표 내부의 짧은 실패 상태와 다시 시도 버튼으로 표시한다. 정상 데이터가 없는 상태와 구분한다.

## 2. 관측 오른쪽 패널

- 문제: 역할 칩과 입력란이 중복되며, 정책 영역의 박스·라벨·저장 버튼이 서로 다른 줄에 배치된다. 긴 리소스 식별자가 정책을 아래로 민다.
- 설계: 상단 기록 요약 박스를 유지한다. 중복 리소스 식별자만 요약 아래에서 펼친다. 요청·응답 → 저장된 연결 판정과 접힌 연결 근거 → 정책 편집 → Request Lab 순서다.
- 정책 외곽 박스와 역할 칩·자유 입력을 제거한다. `필수 역할 지정 / 트래픽 재정의 / 리소스 소유자`를 라벨 + 드롭다운 + 저장의 세 줄로 정렬한다. 필드와 저장 버튼은 높이 32px, 저장 버튼은 폭 60px이다.
- 미지정, Anony, User, LV1, LV2, Admin 및 등록 사용자 역할을 선택할 수 있게 한다. 목업의 Operator는 등록 사용자 역할 예시다. 실제 구현에서는 현재 프로젝트에 등록된 역할과 기존 저장값을 보존해야 한다.
- 선택만으로 저장하지 않는다. 각 저장 버튼을 눌러 반영한다. 목업 저장은 현재 페이지 메모리에서만 동작한다.
- 정책 접기·펼치기는 선택을 유지한다. Request Lab 설명은 도움말 아이콘에서 확인한다.
- 요청·응답은 본문 있음 / 본문 미보존 / 불러오는 중 / 조회 실패 / 연결 기록 없음 상태를 구별한다. 다른 기록의 본문으로 대체하지 않는다.
- 긴 목록 경로는 API 열 안에서 줄바꿈해 HTTP 열과 겹치지 않는다. 판정은 저장된 합성 verdict를 표시하며 HTTP 상태로 산출하지 않는다.

## 검증

`final-check.mjs`를 로컬 Chrome으로 실행했다. 두 해상도 × 두 테마에서 12개 검증 묶음이 통과했다. 16개 기본 전후 캡처와 집계·본문·전체 비교 캡처를 저장했다.

- 필터 결과, 집계 위치와 표 높이 유지, Escape 닫기와 포커스 복귀, API 상세 열기
- 역할 드롭다운, 명시적 저장, 접기 시 선택 유지, 기록 변경 시 선택 초기화, 사용자 역할 옵션
- 경로 넘침 없음, 컨트롤 높이 32px, 실패 재시도, 빈 상태, 본문 마스킹
- 목업 JS 오류 없음, 외부 요청과 POST 요청 없음

검증 기록: `final-verification.json`. 제품 회귀 테스트, Maven 검증, Burp·ZAP·Codex 실제 점검은 이번 목업 작업에서 실행하지 않았다. 구현은 사용자 목업 검토 후 진행한다.

## 상세보기 보완 (사용자 진행 승인 후)

기존 API 상세 목업의 단순 모달을 실제 제품의 오른쪽 패널 구조로 맞췄다. Method·경로·서비스 → H/S/L과 관측/선언/입력 → 입력 표 → 관측·산출물 근거 순서다. 관측 행의 기록 번호·출처·계정과 오른쪽 HTTP 배지를 같은 줄에 맞추고 실제 경로를 다음 줄에 둔다. 목록은 내부 가로 스크롤로 열 폭을 유지한다.

Request Lab 버튼과 도움말 버튼의 높이를 맞춘다. 목업 도움말은 패널 왼쪽 안에 고정하고, 실제 제품은 기존 Portal Tooltip의 경계 회피 기능을 이용해 스크롤 영역에 잘리지 않도록 한다. 화면의 `상세보기 열기` 상태에서 전후를 바로 비교할 수 있다. 이 상태의 개선 전은 사용자가 지적한 이전 목업의 모달 재현이며 실제 제품이 모달을 사용했다는 의미가 아니다.
