# API 비교와 관측 상세 UI 보완

2026-10-03 · FIX/UI_UX · 기준 595b86b

사용자가 상세보기 배치 보완과 진행을 승인했다. 개선 전후 목업을 라이트·다크로 먼저 제시한 뒤 두 화면만 수정했다. QA_TEMP에는 병합하지 않았다.

## 반영한 내용과 이유

- API 제목 아래에 비교 표를 바로 배치했다. 긴 설명·파싱 안내·LLM 실행 요약 박스를 제거하고 기존 필터·집계는 표 헤더 안에 유지했다. 파싱 건수는 집계, 실행 요약은 기존 실행 상태 화면에서 확인한다.
- 선언만 있는 행은 빨간 메시지 대신 HTTP `—`, 관측 `0`, 선언 수로 읽는다. source, 선언·관측 데이터와 필터 의미는 변경하지 않았다.
- API 오른쪽 상세는 Method·경로·서비스, H/S/L과 수치, 입력 비교표, 관측 근거 순서로 정렬했다. 관측 행의 번호·출처·계정과 HTTP 배지를 맞췄다. 상세가 열리면 목록 안에서 가로 스크롤할 수 있다.
- 관측 상세의 긴 경로는 열 안에서 줄바꿈한다. 요청·응답 조회는 아직 받은 결과가 없을 때 `…건`을 표시하지 않으며, 실패 시 기존 조회를 다시 시도할 수 있다. API 좌표가 없는 기록은 그 상태를 명시한다.
- 접힌 정책 편집을 라벨·드롭다운·저장 세 줄로 정렬했다. 선택란과 버튼 높이는 32px, 저장 폭은 60px이다. 초기 역할 선택지는 기존 기본 역할과 등록 계정 역할·기존 저장값을 함께 제공하며, 대소문자를 바꾸지 않는다. 선택만으로 저장하지 않는다.
- 저장된 연결 판정과 상세 근거를 구분하고, 중복 리소스 식별자는 펼쳐서 읽는다. Request Lab과 도움말 버튼 높이를 맞췄다. 기존 Portal Tooltip의 화면 경계 회피를 사용해 안내가 잘리지 않게 했다.

중앙 모달은 목록과 선택 근거를 함께 읽기 어려워 채택하지 않았다. 실제 제품의 오른쪽 패널 구조를 유지했다. 정책의 역할 칩과 자유 입력을 함께 두는 방식은 중복이므로 드롭다운 하나로 정리했다. 서버 저장 API, owner 검증, 마스킹, 과거 기록, 판정 계산은 유지했다. 그래프의 일반 정책 편집은 기존 UI를 유지한다. 모바일·DB 마이그레이션은 범위에 포함하지 않았다.

## 검증과 한계

- 관련 Vitest 3개 파일: 29개 테스트 통과. 역할 저장값 대소문자·사용자 정의 역할 보존, 명시적 저장, 좌표 없는 기록 처리를 포함한다.
- 저장소 루트 `mvn clean verify`: 프론트엔드 620개 테스트 통과, Java 792개 중 789개 통과·3개 기존 건너뜀, 빌드 성공. 로컬 테스트 포트를 허용한 환경에서 실행했다. 최초 실행의 테스트 타입 오류를 수정했으며, 샌드박스 실행은 로컬 포트 차단으로 실패했다.
- `final-check.mjs`: 같은 합성 데이터의 개선 전후 목업 검증 12개 묶음 통과.
- `final-actual-check.mjs`: 실제 웹 빌드 + 읽기 전용 합성 서버, 1280×720·1920×1080 × 라이트·다크. 상세 선택·입력 근거·32px 정렬·정책 접기 시 선택 유지·도움말 화면 경계·마스킹·조회 실패 재시도 등 12개 묶음 통과. 20개 캡처 저장. JS 오류·외부 요청·변경 요청 없음.
- 초기 실제 웹 확인에서 rem 기준 높이가 목업보다 작아 32px로 보완한 뒤 다시 빌드하고 웹 검증을 통과했다.
- 마지막 보완을 포함한 `mvn clean verify`는 13:56 KST에 성공했다. `graphify update .`도 AST 추출로 갱신했다(6,771개 노드·22,580개 엣지, API 호출 없음).

자동 결과는 `final-product-verification.json`, 실제 빌드 화면은 `final-actual-captures/`, 전후 목업은 `final-review.html`에서 확인한다. 목업의 이전 상세 모달은 이전 목업 재현이며 실제 제품의 기존 UI와 구분한다.

Burp 확장 실행, ZAP·Codex 수집, 실제 프로젝트 저장에 대한 수동 QA는 수행하지 않았다. 웹 검증 서버의 저장 버튼은 읽기 전용이므로, 실제 저장 동작은 회귀 테스트와 사용자 로컬 QA로 구분해 확인한다. QA_TEMP 병합과 다음 기능 작업은 별도 승인 대상이다.
