점검 시작

완료되지 않은 단계 하나만 엽니다. 아래 순서대로 진행하면 HUMAN·ZAP·LLM 비교와 Judge 검증까지 이어집니다.

지금 할 일

Burp의 FlowScope 탭에서 허가된 exact scope를 적용하세요.

  1. Burp FlowScope 탭에 http(s)://host[:port]/path-prefix를 입력합니다.
  2. 범위 적용을 누릅니다.
  3. Proxy listener는 HUMAN 127.0.0.1:8080, ZAP 127.0.0.1:8081을 사용합니다.
계정 선택

로그인이 필요하면 계정·세션에서 계정을 등록하고 로그인 연결을 완료한 뒤 pass를 시작하세요. 비로그인 탐색은 바로 시작할 수 있습니다.

확인 중로컬 ZAP 연결
실행 중인 ZAP Desktop 또는 Docker ZAP을 확인합니다.
ZAP Desktop 설정
  1. main proxy/API를 127.0.0.1:8089로 설정
  2. API key를 ~/.flowscope/zap-api-key와 동일하게 설정
  3. Network → Connection → HTTP Proxy를 127.0.0.1:8081로 설정
  4. 키를 새로 만들었다면 FlowScope 확장 재로드

요청 실험실

선택한 Evidence를 편집해 원래 서비스에 전송하고 응답을 비교합니다. 전송 결과는 탐색 커버리지와 분리된 HUMAN 검증 Evidence로 기록됩니다.

고정 대상-
원문 인증값은 이 Burp 프로세스와 현재 브라우저 탭의 메모리에만 표시되며 프로젝트·JSON·로그로 저장하지 않습니다. 리다이렉트는 따라가지 않고 대상 서비스는 변경할 수 없습니다.

첫 점검을 시작하세요

아직 FlowScope Evidence가 없습니다. 분석 그래프보다 아래 수집 순서를 먼저 완료하면 같은 대상에서 사람·ZAP·LLM의 발견 차이를 비교할 수 있습니다.

1
Burp에서 exact scope 적용

FlowScope 탭에 허가된 scheme·host·port·path prefix를 입력합니다.

2
로그인 후 HUMAN pass

필요한 테스트 계정을 캡처하고 명시적 HUMAN pass 동안 기능을 탐색합니다.

3
안전 ZAP 기준선

Traditional·Client·AJAX Spider와 scope 제한 passive 결과를 시스템 순서로 수집합니다.

4
독립 LLM Explorer와 Judge

MCP Explorer를 끝낸 뒤 세 레인을 잠그고 Evidence 기반 검증을 수행합니다.

ADMIN 계정은 필수가 아닙니다. 기본 BOLA 비교에는 서로 다른 최소 권한 테스트 계정 2개를 권장하며, BFLA 역할 비교가 필요할 때만 관리자 역할을 추가합니다.

계정·세션 관리

등록 계정(Identity)은 유지하고 로그인 세션만 새로 연결합니다. raw 인증값은 Evidence·프로젝트에 저장하지 않고 broker 메모리에만 둡니다.

테스트 계정 등록

표시 이름·역할·대상 서비스만 등록합니다. 로그인 캡처 중 받은 쿠키·토큰은 Burp 프로세스 메모리에만 유지되고 프로젝트 파일에는 저장되지 않습니다.

등록 계정과 로그인 상태

일반 사용에서는 계정 하나만 확인하면 됩니다. 쿠키·토큰·subject 단서는 같은 로그인 세션의 내부 근거로 묶이며 기본 화면에는 따로 표시하지 않습니다.
