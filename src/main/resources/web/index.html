FlowScope 베타 빠른 시작

사용자가 해야 하는 것은 범위·계정 확인과 능동 요청 승인뿐입니다. 수집·비교·후보화·검증 판정은 FlowScope와 구독 LLM이 이어서 처리합니다.

1
진단 범위 고정

Burp의 FlowScope 탭에서 정확한 http(s) 서비스와 경로 prefix를 입력하고 범위 적용을 누릅니다. 빈 범위에서는 ZAP·LLM 능동 요청이 차단됩니다.

사용자 확인
2
수집 경로 분리

Burp Proxy listener를 사람 8080, ZAP 8081로 둡니다. LLM은 MCP 통제 실행기를 사용하며 8082는 외부 클라이언트 수동 폴백뿐입니다. 공급자 로그인/OAuth/MCP 트래픽은 절대 프록시하지 않습니다.

대기
3
계정 로그인과 사람 기준선

계정·세션에서 테스트 계정을 등록하고 로그인 캡처를 누른 뒤 HUMAN 8080 브라우저로 직접 로그인합니다. 캡처 종료 후 HUMAN pass 시작을 눌러 허용된 일반 사용자 워크플로를 둘러보고 같은 run을 종료합니다.

pass 대기계정 선택
4
결정론적 ZAP 기준선

아래에서 비로그인과 ACTIVE 계정을 복수 선택합니다. FlowScope가 신원마다 ZAP 세션을 새로 만들고 Traditional Spider → Client Spider(AJAX 폴백) → Passive Scan → 네이티브 Alert를 순서대로 실행합니다. 능동 스캔은 별도 승인 없이는 실행하지 않습니다.

미실행
5
독립 LLM Explorer

Burp 탭의 MCP 연결 문자열을 구독 Codex/Claude에 등록하고 agent-workspace의 Explorer 지침을 실행합니다. Explorer는 서버가 제공한 통제 요청만 사용하며 사람·ZAP 결과를 보지 못합니다.

대기
6
잠금 후 Judge 최종 판정

세 소스를 잠근 다음 Judge가 갭과 ZAP Alert를 읽고 후보별 재현·정상 계정 대조를 수집합니다. 통제 Evidence가 서버 검증을 통과해야 CONFIRMED/REJECTED가 되며, 부족하면 INCONCLUSIVE입니다.

대기
격리 실행할 신원
ZAP 연결과 허용 범위를 확인하는 중입니다.

첫 점검을 시작하세요

아직 FlowScope Evidence가 없습니다. 분석 그래프보다 아래 수집 순서를 먼저 완료하면 같은 대상에서 사람·ZAP·LLM의 발견 차이를 비교할 수 있습니다.

1
Burp에서 exact scope 적용

FlowScope 탭에 허가된 scheme·host·port·path prefix를 입력합니다.

2
로그인 후 HUMAN pass

필요한 테스트 계정을 캡처하고 명시적 HUMAN pass 동안 기능을 탐색합니다.

3
안전 ZAP 기준선

Traditional·Client Spider와 passive 결과를 시스템 순서로 수집합니다.

4
독립 LLM Explorer와 Judge

MCP Explorer를 끝낸 뒤 세 레인을 잠그고 Evidence 기반 검증을 수행합니다.

ADMIN 계정은 필수가 아닙니다. 기본 BOLA 비교에는 서로 다른 최소 권한 테스트 계정 2개를 권장하며, BFLA 역할 비교가 필요할 때만 관리자 역할을 추가합니다.
