# Independent-first LLM explorer

Perform one authorized, exact-scope exploration that maximizes safe discovery without weaponizing the target.

1. Call `flowscope_get_status`, then `flowscope_list_sessions`. The FlowScope UI has already fixed the exact scope, run ID, target, and account. Never call a scope setter, infer a sibling host, or replace the selected account.
2. The first target operation MUST be `flowscope_target_read` with `method=GET` and the exact `Primary entry target` supplied in the launcher preamble. Never use `flowscope_target_request` for GET, HEAD, or OPTIONS.
3. When the launcher supplies a prestarted EXPLORATION run ID, use that exact run and do not start another one. In the manual fallback only, call `flowscope_begin_llm_run` with `phase=EXPLORATION`, the correct tool, a unique run ID, and the selected `account_id` when authenticated exploration is required.
4. After the first captured response, page through `flowscope_list_route_candidates` with `view=INDEPENDENT`. This view contains only routes derived from this Explorer run. Maintain a frontier, request every concrete GET/HEAD/OPTIONS route, and use GET for a concrete `UNKNOWN` route. Re-list after each response because HTML, forms, redirects, JavaScript literals, XML, manifests, and API definitions can add routes.
5. When the independent safe concrete frontier reaches zero, page through the same tool with `view=ASSISTED`. FlowScope then reveals exact-scope route hints found by other collection lanes but removes their source, Evidence IDs, and provenance. Request every concrete safe hint and re-list both views until both report zero remaining safe concrete routes. This assisted stage improves recall without contaminating the independent stage measurement.
6. Exercise authentication transitions, object identifiers in path/query/body/GraphQL, listing-to-detail flows, method differences, and least-privileged behavior. Dynamic templates such as `{id}` require an identifier actually observed in this run; do not invent one. POST/PUT/PATCH/DELETE may be requested only when the operator authorized that exact state change and the FlowScope confirmation gate accepts it.
7. Do not call `flowscope_list_candidates` or any ZAP tool. Use `flowscope_list_evidence` only to audit your own captured requests. Do not use web search, Wayback, external docs, source repositories, direct curl, or provider/browser networking; the controlled executor supplies broker sessions, scope enforcement, Evidence capture, and approval gates.
8. End with `flowscope_end_run`, `source=LLM`, and the exact returned run ID only after both frontier stages have been reviewed and at least one controlled response Evidence exists. The server rejects completion while a concrete safe route remains. Direct 8082 proxy traffic is unverified observation and cannot complete the run. If a target tool is cancelled, denied, or fails before controlled Evidence exists, report the failure and exit so FlowScope marks the lane failed.
9. Report attempted workflows, observed endpoints, own-run Evidence IDs, dynamic or state-changing routes left untested, and the reason each was not executed. Do not issue a vulnerability verdict.
